# dobby-perf

오더 하나를 재서 `perf.json` **하나만** 쓴다. 다른 파일은 건드리지 않는다.

## 설정

`${CLAUDE_PLUGIN_ROOT}/reference/config.md` 의 "설정 절차"를 그대로 따른다. 헬퍼는 bash 로 부른다.

```bash
bash -c 'source ~/.config/go-dobby/config.env; source "${CLAUDE_PLUGIN_ROOT}/reference/dobby-lib.sh"; dobby_load_config; dobby_perf_measure {키}'
```

## 사용법

```
/dobby-perf {키}        # 그 오더를 재서 perf.json 을 새로 쓴다
/dobby-perf {키} regen  # 같은 동작(이미 있어도 다시 잰다)
```

- 다시 재면 덮어쓴다. 측정 시각은 파일 안 `measuredAt` 에 남는다.
- 상태 문서에 `## 지난 세션` 표가 없는 오더는 잴 수 없다. 헬퍼가 "측정 불가"를 내면 그 줄을 그대로 보이고 끝낸다.

## 순서

1. `dobby_perf_measure {키}` 를 부른다. **출력된 요약만 읽는다.** 세션 기록을 직접 열지 않는다.
2. 해석이 더 필요하면 `perf.json` 에서 `totals`, `byStage`, `items`, `sleepLog` 만 읽는다.
3. 해석 문장을 임시 파일(`$TMPDIR` 아래)에 `{"summary": "…"}` 로 쓰고 `dobby_perf_put {키} {파일}` 로 합친다. `summary` 밖의 칸은 거부된다. 숫자는 고칠 수 없다.
4. `dobby_perf_lint {키}` 가 통과할 때까지 문장을 고쳐 3을 다시 한다.
5. 사람에게 요약을 보인다. 자동 실행 시간, 개선 전 기준 시간, 줄어든 시간, 적용된 개선, 해당 없는 개선과 그 이유를 쉬운 말로 적는다.

## 해석 문장(summary) 규칙

- 3~5문장으로 쓴다. 한 문장은 60자 안팎으로 끊는다. 100자를 넘으면 검사가 거부한다.
- 쉬운 말로 쓴다. 파일 이름, 칸 이름(`savedMin` 같은 것), 단계 코드, 화살표(`→`)는 쓰지 않는다.
- 숫자는 파일에 있는 값만 쓴다. 새로 계산하거나 짐작한 숫자를 넣지 않는다.
- 다음을 차례로 담는다.
  1. 이 오더의 자동 실행 시간과 개선 전 기준 시간의 차이
  2. 차이를 가장 크게 만든 단계와 그 까닭(근거 칸에 있는 사실만)
  3. 적용된 개선과 줄어든 시간. 적용된 것이 없으면 그 사실
  4. 잠든 시간이나 사람을 기다린 시간이 크면 그 사실(합계에 넣지 않았다는 것까지)
- 기준 시간은 많은 오더의 평균이다. 오더 하나와의 차이가 곧 개선 효과는 아니라는 점을 문장에 밝힌다.

## 헬퍼가 재는 것

| 값 | 재는 방법 |
|---|---|
| 세션 구간(자동 세션) | 지난 세션 표의 한 행에서 같은 세션의 다음 행 앞까지 |
| 세션 구간(사람이 터미널에서 연 세션) | 다른 일과 섞이므로 좁힌다. 시작은 행 시각 앞 60분 안에 사람이 친 줄 가운데 오더 키가 든 마지막 줄, 없으면 마지막 줄(그 행을 적은 차례의 시작)이다. 새로 연 세션(첫 사건이 행 시각 앞 60분 안)은 세션 첫 사건부터다. 끝은 같은 세션의 다음 행 시작, 표의 바로 다음 행(다른 세션)이 실제로 시작한 때, 같은 세션을 쓴 다른 오더의 시작 가운데 가장 이른 것이다. 다른 오더는 메타 폴더의 다른 상태 문서에서 같은 세션 아이디를 찾아 안다 |
| 사람과 대화한 세션 | 구간 안에서 사람이 친 줄이 2개 이상이거나, 사람이 터미널에서 연 세션(기록의 `entrypoint` 가 `cli`)이고 세션 전체에 사람이 친 줄이 2개 이상. 자동 실행 합계와 기준에서 빼고 `interactive` 에 모델 시간과 도구 시간의 합만 둔다 |
| 잠든 시간 | 컴퓨터 잠자기 기록(`pmset -g log`)의 잠듦 줄부터 다음 깨어남 줄까지. 세션 시간에서 빼고 `sleepMin` 에 둔다. 기록은 약 일주일만 남는다. 못 뺀 경우 `sleepLog` 에 이유가 있다 |
| 자동 실행 시간 | 자동 세션 구간을 합치되 겹친 시간은 한 번만, 잠든 시간은 뺀다 |
| 기준 시간 | 단계별 세션 수에 기준 평균(구현 6.0분, 리뷰 3.6분, 통합 1.6분, 배포 2.1분, 검증 6.3분)을 곱한다. 다섯 단계 밖의 자동 세션은 실제 시간을 그대로 넣는다 |
| 사람을 기다린 시간 | 이벤트 로그의 `사람 차례`, `막힘` 줄부터 같은 담당자의 다음 줄 또는 다음 세션 시작 중 이른 때까지. 합계에 넣지 않는다 |
| 개선 항목 | 아래 표 |
| 토큰 흐름 | 아래 "토큰 흐름" 절 |

| 개선 | 적용 판정 |
|---|---|
| 타입 검사 기본 끔 | 타입 검사 호출 출력에 `건너뜀` 이 있음. 개선 전처럼 직접 검사한 기록만 있으면 해당 없음이고, 그 횟수와 시간을 근거에 남긴다. 둘이 섞이면 줄어든 시간은 `null` |
| 켠 오더의 타입 검사 재사용 | 상태 문서에 `- **타입 검사**: 켬` 줄 |
| 작은 검증 묶음 합치기 | 단계 이름에 `+` 가 든 검증 세션 |
| 검증 묶음 동시 실행 | 이벤트 로그에 `검증 동시 실행(` 줄 |
| 배포 대기 확인 간격 줄이기 | 대시보드 자동 실행 기록(`.mentis-jobs/{키}/run.log`)의 기다림 줄 간격이 1분 이하. 기록이 없으면 `null` |
| 통합 단계 문서 쓰기 나누기 | 상태 문서에 `- **결과 문서**:` 줄 |
| 의존성 설치 줄이기 | 구현 세션이 모두 플러그인 0.2.151 이상으로 돌았음(세션 기록의 `go-dobby/{판}/` 경로) |
| 검증 화면 확인 묶기 | 검증 세션이 모두 플러그인 0.2.151 이상으로 돌았음. 시나리오 하나당 응답 수를 근거에 남긴다 |

적용 전인 개선도 지금 값을 근거에 남긴다. 나중에 개선 뒤 오더와 비교하기 위해서다.

## 토큰 흐름

세션 행의 `ctx` 와 최상위 `tokenFlow` 에 쓴다. 기존 칸(`tokens` 등)의 뜻은 그대로다. 사람과 대화한 세션도 토큰 흐름에는 넣는다.

| 값 | 재는 방법 |
|---|---|
| 호출의 컨텍스트 크기 | 응답 하나의 새 입력 + 캐시 쓰기 + 캐시 읽기. `ctx.series` 에 호출 순서대로 둔다 |
| 고정 바닥 `floor` | 새로 시작한 세션은 그 세션의 첫 호출 크기. 이어 쓴 구간은 이 오더의 새 세션 첫 호출 크기 가운데 값(`tokenFlow.floorRef`). 새 세션이 하나도 없으면 `null` 이고 몫을 나누지 않는다 |
| 이월된 대화 `carry` | 이어 쓴 구간의 첫 호출 크기 − 고정 바닥. 새 세션은 0 |
| 입력 합계 `sum` | 호출별 컨텍스트 크기의 합. 고정 바닥 몫(`floor × 호출 수`), 이월 몫(`carry × 호출 수`), 나머지인 쌓인 대화 몫으로 나눈다 |
| 캐시 적중률 | 캐시 읽기 합 ÷ 입력 합계 |
| 캐시 다시 쓰기 | 캐시 읽기가 직전 호출 크기의 절반 아래인 호출의 순번. 구간 첫 호출은 같은 세션의 직전 호출과 견준다 |
| 압축 | 컨텍스트 크기가 직전 호출의 70% 아래인 호출의 순번 |
| 비용 `costUsd` | 세션 기록의 마지막 `cost-state` 줄. 그 줄이 없거나, 한 세션이 여러 구간으로 나뉘거나, 다른 오더와 함께 쓴 세션이면 `null` |
| 뺀 호출 `tokenFlow.excluded` | 사람과 대화한 세션에서 이 오더의 첫 구간 시작부터 다른 오더의 시작(없으면 세션 끝)까지 가운데 어느 구간에도 들지 않은 호출. 다음 세션에 일을 넘긴 뒤 진행을 확인한 호출이 여기에 든다. 호출 수와 입력 합계만 남긴다 |
| 서브 에이전트 `subagents` | 세션 기록 옆 `{세션 아이디}/subagents/agent-*.jsonl` 에서 구간 안의 응답을 센다. 세션 행과 `tokenFlow.subagents` 에 따로 두고 `tokenFlow.sum` 에는 넣지 않는다. 기록이 없으면 칸이 없다 |

`tokenFlow.input` 은 캐시를 거치지 않은 입력만이다. 기존 `tokens.input` 은 캐시 쓰기를 더한 값이라 서로 다르다.
