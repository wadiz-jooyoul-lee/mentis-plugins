# 사람에게 묻는 법 (질문을 남겨야 할 때만 읽는다)

`/do` 세션이 스스로 정할 수 없는 일을 만났을 때 질문을 남기는 방법이다. 언제 묻는지는 `SKILL.md` 의 "스스로 정하고, 꼭 필요할 때만 묻는다" 표에 있다. 그 표에 들지 않으면 묻지 않고 스스로 정한다.

질문은 사람이 메타를 열어 보지 않고도 답할 수 있게 일곱 칸을 채운다. 쉬운 말로 쓴다. 파일 이름, 담당자 식별 이름, 회차 번호, 헬퍼 이름 같은 내부 낱말을 쓰지 않는다.

| 칸 | 내용 | 파일의 이름 |
|---|---|---|
| 질문 한 줄 | 무엇을 정해 달라는지 | `title` |
| 무슨 일이 있었나 | 어디까지 진행했고 무엇에서 걸렸는지 | `what` |
| 왜 스스로 정하지 못했나 | 사람에게 묻는 경우 가운데 어느 것인지 | `why` |
| 지금까지 해 본 것 | 시도한 것과 결과를 한 줄씩 | `tried` (글 목록) |
| 방법들 | 방법마다 무엇을 하는지, 고르면 어떻게 되는지. 권하는 방법과 이유 | `options` (목록) |
| 답하는 방식 | 아래 넷 중 하나 | `kind` |
| 답한 뒤 | 답하면 무엇이 이어지는지 | `after` |

| 답하는 방식 | `kind` | 더 적을 것 | 답으로 오는 값 |
|---|---|---|---|
| 예 / 아니오 | `yesno` | 질문 한 줄을 예·아니오로 답할 수 있는 문장으로 쓴다. 방법들은 없어도 된다 | `예` 또는 `아니오` |
| 하나 고르기 | `choice` | 방법 2~3개. 방법마다 `label`(이름), `does`(무엇을 하는지), `effect`(고르면 어떻게 되는지). 권하는 방법 하나에 `recommended: true` 와 `reason` | 고른 방법의 이름, 또는 사람이 적은 다른 의견 |
| 글로 적기 | `input` | `todo` 에 무엇을 적을지와 예시 | 적은 글 |
| 직접 해 주기 | `action` | `todo` 에 할 일과 명령. 됐는지 확인하는 명령이 있으면 `check` | `했어요`(확인 명령이 있으면 통과해야 이어 간다) |

질문 초안을 JSON 파일로 쓰고 헬퍼로 남긴 뒤 끝 헬퍼를 부른다. 초안은 오더 메타 폴더에 아무 이름으로 쓰면 된다(받아들이면 헬퍼가 지운다).

```json
{
  "kind": "choice",
  "title": "쿠폰 금액이 0원일 때 쿠폰 영역을 숨길까요, \"0원\"으로 보여 줄까요?",
  "what": "rc4 배포까지 마쳤고, 코드 리뷰에서 같은 지적을 세 번 받았습니다. 지적 내용: 0원 쿠폰이 화면에 보이면 받을 수 있는 쿠폰으로 오해한다.",
  "why": "이슈에는 쿠폰 금액을 표시한다고만 적혀 있습니다. 숨기면 이슈가 요구한 결과와 달라져서 저희가 정할 수 없습니다.",
  "tried": ["0원으로 표시 → 리뷰에서 오해 소지 지적", "회색 글씨로 표시 → 같은 지적", "안내 문구를 덧붙임 → 같은 지적"],
  "options": [
    {"label": "가", "does": "0원이면 쿠폰 영역을 숨깁니다.", "effect": "리뷰 지적이 사라집니다. 이슈의 요구와는 달라집니다.", "recommended": true, "reason": "같은 지적이 세 번 나왔습니다."},
    {"label": "나", "does": "지금처럼 0원으로 보여 주고 리뷰 지적은 반영하지 않습니다.", "effect": "이슈 요구대로입니다. 리뷰 승인 없이는 합칠 수 없어 직접 합치셔야 합니다."}
  ],
  "after": "고르신 방법으로 설계를 고치고, 구현부터 rc4 확인까지 다시 진행합니다."
}
```

```
dobby_v2_ask {키} file {초안 파일 경로}
dobby_v2_end {키} 질문
```

- 헬퍼가 검사한다: 칸이 다 찼는가, 답하는 방식이 넷 중 하나인가, 하나 고르기의 방법마다 "고르면 어떻게 되는지"가 있는가, 내부 낱말이 없는가. 어기면 `거부:` 줄을 낸다. 고쳐서 다시 부른다. 거부를 피하려고 칸을 빈말로 채우지 않는다.
- 헬퍼가 채우는 것: 묻는 담당자와 세션, 그 세션이 시작한 폴더, 답 뒤에 그 세션을 이어 띄울지(테스터와 배포담당만).
- `질문` 으로 끝내면 단계는 그대로다. 자기 행이 `사람 차례` 가 되고, 자동 실행이 답을 기다린다. 8시간(`DOBBY_ASK_MAX`) 답이 없으면 자동 실행은 멈추지만 질문은 남는다. 그 뒤 답하면 자동 실행이 다시 띄워진다.
- 답이 오면: 테스터와 배포담당의 질문은 그 세션이 이어서 띄워진다(문맥이 12만 토큰을 넘으면 새 세션). 그 밖에는 새 세션이 띄워진다. 어느 쪽이든 시작 헬퍼 결과에 `질문과 답:` 이 붙는다. 질문 전에 하던 일을 이어서 하고, 같은 것을 다시 묻지 않는다.
- 비밀번호는 묻지 않는다. 시험 계정은 config.env 에 있다.
- **대화형 세션(사람이 터미널에 있음)에서는 질문을 남기지 않고 그 자리에서 묻는다.**
- 옛 방식(설계 문서 `## 확인이 필요했던 것` 에 적고 `판단요청` 으로 끝내 단계를 보류로 바꾸는 것)과 `/do {키} 답 "…"` 은 보류된 옛 오더와 자동 실행 없이 터미널에서만 돌리는 오더를 위해 남아 있다. 자동 실행이 띄운 세션은 쓰지 않는다. 보류가 되면 자동 실행이 끝나고 사람이 `/do {키}` 를 직접 쳐야 한다.
