# 세션 5 · 통합

## 하는 일

1. `dobby_session_log {키} {슬러그} integrate 통합 {워크트리경로}` 로 세션을 기록하고, 리뷰 결과가 0 건인지 다시 확인한다 — `dobby_blocking {키} {N}`.
2. 커밋하고 푸시한다 — `dobby_commit_push {워크트리} {브랜치} "{메시지}"`.
   - 메시지는 `fix: {키} {무엇을 고쳤는가}` 또는 `feat: {키} {무엇을 만들었는가}`.
   - **오케스트레이션 내부 용어를 넣지 않는다**(라운드 번호, 슬러그, 단계 코드, "리뷰 반영").
   - 저장소가 금지하는 서명을 넣지 않는다.
3. 에이전트 브랜치가 루트 브랜치와 다르면 머지한다 — `dobby_merge_root {워크트리} {루트브랜치} {에이전트브랜치}`.
4. `outcome.md` 를 쓴다 — `dobby_scaffold_doc {키} outcome` 후 설계 대비 결과 표와 구현 내용을 채운다. 내부 용어와 줄임말을 쓰지 않는다(`dobby_terms_lint` 로 확인).
5. `dobby-explain {키}` 를 실행해 비전공자용 구현 내용 문서를 만든다.
6. 변경을 통합했으면 설계 문서의 그 `## 변경 {M}` 절 상태를 `통합됨 ({커밋 해시 7자리})` 로 바꾼다. `outcome.md` 는 덮어쓰지 않고 `## 후속 {YYYY-MM-DD} — {변경 요약}` 절을 덧붙인다. 상태를 바꾸지 않으면 다음 변경 때 구현 세션이 이미 통합된 변경을 다시 구현하려 한다.

**정식 배포 브랜치로 PR 을 만들거나 머지하지 않는다.** 그것은 `dobby-ship` 이 할 일이다.

## 마무리

```
dobby_agent_state {키} {슬러그} 완료
dobby_phase {키} 통합
dobby_event {키} "통합 완료 — 검증 세션으로 넘김"
```

자동 배포 오더면 다음은 배포 세션이다. 이벤트 문구의 "검증 세션"을 "배포 세션"으로 바꿔 적는다.
