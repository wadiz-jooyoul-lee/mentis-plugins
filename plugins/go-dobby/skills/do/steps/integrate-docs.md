# 결과 문서 세션 (배포담당)

자동 배포 오더의 통합이 커밋·푸시만 하고 끝나면, 자동 실행이 이 세션을 배포와 함께 백그라운드로 띄운다(`/do {키} 결과 문서`). 이 세션은 문서 두 개만 쓴다.

- 배포 세션이 함께 돈다. **상태표 행, 배포 표, 설계 문서, 코드는 건드리지 않는다.** 커밋과 푸시도 하지 않는다.
- 브라우저 도구가 붙어 있지 않다. 근거는 메타 문서와 작업 폴더의 git 기록에서 찾는다.
- 사람에게 묻지 않는다. 쓸 수 없으면 끝 헬퍼를 부르지 않고 이유를 남긴 채 끝낸다. 자동 실행이 멈추고 사람에게 알린다.

## 하는 일

1. 결과 문서(`outcome.md`)를 쓴다. 시작 헬퍼의 `설명:` 줄로 가른다.
   - `결과 문서 처음 쓰기`: `dobby_scaffold_doc {키} outcome` 후 설계 대비 결과 표와 구현 내용을 채운다.
   - `결과 문서 후속 덧붙이기`: 덮어쓰지 않는다. 설계 문서에서 상태가 `통합됨` 인 `## 변경 {M}` 절 가운데 `outcome.md` 에 아직 없는 것마다 `## 후속 {YYYY-MM-DD} — {변경 요약}` 절을 덧붙인다.
   - 내부 용어와 줄임말을 쓰지 않는다. `dobby_terms_lint` 로 확인한다.
2. `dobby-explain {키}` 를 실행해 비전공자용 구현 내용 문서(`explainer.md`)를 만들거나 후속 절을 덧붙인다.

## 마무리

```
dobby_v2_docs_end {키}
```

끝 헬퍼는 시작 뒤 `outcome.md` 와 `explainer.md` 를 고쳤는지 확인하고, 상태 문서의 `- **결과 문서**:` 줄을 `완료` 로 바꾼다. `거부:` 가 나오면 빠진 문서를 쓰고 다시 부른다. 끝 헬퍼 출력을 그대로 알리고 끝낸다.
