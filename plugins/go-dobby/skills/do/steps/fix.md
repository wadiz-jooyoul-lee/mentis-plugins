# 세션 4 · 수정

## 읽을 것

1. 최신 차수의 리뷰 결과 파일 — `$ORCHESTRATION_META/{키}/reviews/round-{N}/review-agent.md`. dobby-order 에서 옮겨 온 오더는 파일 이름이 다를 수 있다(예: `inline-dev.md`). 그 폴더의 `.md` 파일을 전부 읽는다.
2. `design.md` — 설계 기준.

검증 실패는 이 세션으로 오지 않는다. 기획자가 실패를 분석해 설계 문서에 변경 절로 적고, 구현 세션이 그 변경을 구현한다.

## 하는 일

1. 워크트리에서 `[blocker]` 와 `[major]` 를 전부 반영한다. `[minor]` 와 `[nit]` 은 판단해서 처리하고, 안 할 거면 이유를 적는다.
2. 반영한 내용을 `implementation.md` 에 덧붙인다.
3. **커밋하지 않는다.**

## 지적을 반영하지 않기로 할 때

"드물다"·"엣지 케이스다" 같은 **빈도 추정은 근거가 아니다.** 그 상태를 만드는 코드 경로를 `파일:라인` 으로 전수 확인해 **0건임을 증명**했을 때만 기각한다. 1건이라도 남으면 반영한다. 증명하지 못하면 반영한다.

## 마무리

```
dobby_v2_end {키} 완료
```

끝 헬퍼가 다음 차수의 빈 리뷰 폴더를 열고 리뷰어 차례로 넘긴다. **반영했으면 반드시 다시 리뷰한다.**

**차수가 3을 넘으면 멈춘다.** 3차 리뷰의 지적을 반영하는 수정 세션이면 반영은 하되 `완료` 대신 `dobby_v2_end {키} 막힘 "{무엇이 왜 안 닫히는지}"` 로 끝낸다. 그러면 다음 차수가 열리지 않고 사람 차례가 된다. 변경을 리뷰하는 중이면 그 변경 절의 `리뷰 시작 차수` 부터 센다. 예를 들어 시작 차수가 4차면 6차가 마지막이다.
