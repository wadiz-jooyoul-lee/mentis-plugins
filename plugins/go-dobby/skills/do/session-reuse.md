# 세션 이어 쓰기 판정 (근거)

`/do` 는 단계마다 새 세션이 기본이다. 이 문서는 언제 직전 세션을 이어 쓰는 쪽이 싼지와 그 근거를 적는다. 판정은 `reference/dobby-lib.sh` 의 `dobby_v2_reuse_ok` 한 곳에서 한다. 이 판정을 쓰는 곳은 둘이다.

| 쓰는 곳 | 하는 일 |
|---|---|
| `run.sh`(자동 실행) | 이어 쓰는 쪽이 싸면 `claude -p --resume {직전 세션}` 으로 다음 세션을 띄운다 |
| 대화형 세션 마무리(`dobby_v2_next_hint`) | 이어 쓰는 쪽이 쌀 때만 `다음` 칸에 "/clear 없이 이어서" 안내를 낸다. 아니면 아무것도 출력하지 않는다 |

이 문서는 SKILL.md 에 넣지 않는다. 스킬 본문은 세션마다 문맥에 실려 호출마다 다시 읽힌다. 근거 설명까지 넣으면 그 비용이 판정으로 아끼는 양보다 커진다.

## 조건과 근거

기본은 단계마다 새 세션이다. 아래를 **모두** 만족할 때만 `run.sh` 가 직전 세션을 `claude -p --resume {직전 세션}` 으로 이어 쓴다. 이어 써도 세션 아이디는 그대로다.

| 조건 | 기준 | 왜 |
|---|---|---|
| 이번에 할 일이 수정이다 | 단계 판정 표의 "수정" 두 줄과 같은 조건(리뷰 지적이 남음, 또는 검증 실패) | 수정은 직전 리뷰·검증 세션이 본 것을 그대로 이어받는다. 리뷰는 독립성이 필요해 이어 쓰지 않는다 |
| 직전 세션의 마지막 문맥이 작다 | 120,000 토큰 이하 | 이어 쓰면 호출마다 그 문맥 전체를 다시 읽는다 |
| 직전 호출 뒤 오래 지나지 않았다 | 300초(5분) 이하 | 캐시가 만료되면 누적 문맥 전체를 비싼 값으로 다시 캐시에 쓴다 |

근거는 FE1-2139~FE1-2142 의 세션 기록 34개를 잰 값이다. 비용은 캐시 안 쓴 입력 1 기준으로, 캐시 쓰기 5분 1.25배, 1시간 2배, 캐시 읽기 0.1배로 환산했다.

- 새 세션의 시작 문맥은 5.7만~9.2만 토큰이고, 첫 호출 비용은 4.3만~10만이다.
- 이어 쓰면 호출마다 0.1 × (직전 문맥 − 새 시작 문맥)을 더 낸다. 수정 세션은 15~21번 호출하므로, 직전 문맥이 12만을 넘으면 새 세션보다 비싸다.
- 실제 사례: 문맥 17.7만인 검증 세션을 이어 쓴 수정(`31d5011c`)은 17번 호출에 36.9만이 들었다. 새 세션으로 연 수정(`239e1ba6`)은 16번 호출에 28.4만이었다.
- 캐시 유지 시간은 대화형 세션에서 5분, 헤드리스 세션에서 1시간이 관측됐다. 확인될 때까지 짧은 쪽에 맞춘다.

검증 세션은 끝날 때 문맥이 10만~23만이라, 검증 실패 뒤의 수정은 대부분 새 세션이 된다. 이 판정은 크게 아끼는 장치가 아니다. 이어 쓰다가 손해 보는 경우를 막는 장치다.

## 대화형 안내의 비용

| 항목 | 값 | 근거 |
|---|---|---|
| 판정 계산 | 모델 토큰 0 | 셸(jq)이 세션 기록 파일을 읽어 계산한다. 마무리 때 이미 부르는 명령에 붙여 도구 호출이 늘지 않는다 |
| 평소(이득 아님) | 0 | 아무것도 출력하지 않는다 |
| 이득일 때 | 약 1,000 | 안내 세 줄(도구 출력 약 220토큰을 캐시에 씀)과 마지막 응답에 옮겨 적는 출력 약 150토큰(출력은 입력의 5배로 셈) |
| SKILL.md 에 더한 지시 | 약 2줄 | 세션마다 실린다. 그래서 짧게 둔다 |
| 이득일 때 아끼는 양 | 약 3.7만(추정) | FE1-2139 검증 세션 `e0cca658`(끝 문맥 102,446) 다음의 검증 실패 수정. 실제 새 세션 비용 28.4만에서 첫 호출 7.4만을 아끼고, 호출마다 더 읽는 약 2.6만을 더 낸다 |

네 오더(FE1-2139~FE1-2142)의 세션 전환 약 30번 중 이어 쓰기가 이득이었던 경우는 1번이다. 그래서 매번 출력하면 판정 비용(30번 × 약 1,000)이 아끼는 양(약 3.7만)과 비슷해진다. 이득일 때만 출력하는 이유다.

대화형은 사람이 언제 다음 명령을 칠지 모른다. 캐시(5분)가 지난 뒤 이어 쓰면 누적 문맥 전체를 다시 캐시에 써서 새 세션보다 비싸다. 그래서 안내에 기한(지금+4분)을 적는다.

## 설계 넘기기 — 긴 세션에서 설계를 시작하지 않는다

`/do` 는 단계마다 새 세션을 열지만, **설계와 변경 접수만은 사람이 쓰던 세션에서 그대로 시작된다.** 사람은 보통 한 세션에서 묻고 조사하다가 "이제 설계하자"며 `/do` 를 치기 때문이다. 그러면 설계의 모든 호출이 그 전 대화 전체를 끌고 다닌다. 그래서 시작 헬퍼(`dobby_v2_begin`)가 설계 작성·변경 접수 차례이고 늘어난 문맥(`dobby_v2_ctx_growth`)이 `DOBBY_HANDOFF_MAX_GROWTH`(6만 토큰, config.env 로 조정)를 넘으면 `넘김 권장` 을 내고, 세션은 `steps/handoff.md` 대로 넘김 문서만 쓰고 끝낸다. 입력 검사 훅의 G19(25만 차단)도 이 차례에는 막지 않고 시작 헬퍼로 보낸다 — 막아 버리면 쌓인 조사 내용이 /clear 로 그냥 사라진다.

근거는 끝난 오더 `TASK-antd-removal` 의 세션 기록 실측이다(입력 토큰 환산: 입력 1, 1시간 캐시 쓰기 2, 캐시 읽기 0.1, 출력 5).

| 단계 | 호출 | 문맥 (시작 → 끝) | 비용 |
|---|---|---|---|
| 설계 (닷새 쓴 세션에서 시작) | 52 | 181k → 353k | 2.52M |
| 변경 1 접수 (설계 세션에 이어 붙음) | 37 | 354k → 425k | 1.78M |
| 구현·리뷰·수정·통합 여섯 세션 합 | 235 | 모두 53k 안팎에서 시작 | 5.79M |

설계와 변경 접수가 오더 전체(10.09M)의 43% 를 썼다. 설계를 새 세션에서 했다면 약 0.7M, 변경 접수도 새 세션이면 약 1.0M 이 줄었다(어림 — 오더 전체의 약 17%).

기준 6만의 계산: **절대 문맥이 아니라 "이 세션 첫 호출 뒤로 얼마나 쌓였나"로 잰다.** 대화형 세션은 시작 문맥이 이미 8.8만~11.4만이라(위 light 절) 절대값 기준은 시작하자마자 걸린다. 넘기면 새 세션 첫 호출 4.3만~10만(위 "조건과 근거")과 넘김 문서 쓰기·기록 조회 약 3만을 더 내 합이 약 10만이다. 넘기지 않으면 호출마다 0.1 × 쌓인 문맥을 더 내고, 설계 세션은 약 50번 호출하므로 쌓인 문맥 2만이 본전이다. 사람이 세션을 갈아타는 수고와 요약에서 빠질 위험을 감안해 6만(약 30만 절감)부터 권한다. 다른 오더의 설계 세션 호출 수가 쌓이면 재서 조정한다.

쌓인 문맥이 거의 이 오더를 위한 조사라면 그 자리에서 설계하는 편이 나을 수 있다. 그래서 판정이 나와도 세션이 한 줄로 묻고("넘김 / 그대로 진행"), 사람이 그대로 가자고 하면 `dobby_v2_begin {키} 그대로` 로 진행한다. 사람 없는 실행(run.sh·대시보드 잡, `DOBBY_V2_CHAINED`)과 헤드리스(`claude -p`)는 늘 새 세션이라 이 판정을 타지 않는다. light 도 타지 않는다 — 속도가 먼저이고, 자체 상한(아래 절)이 따로 있다.

## light — 한 세션 실행의 문맥 상한

`/do {키} light` 는 단계를 나누지 않고 세션 하나에서 끝까지 간다(`steps/light.md`). light 는 비용보다 속도가 먼저인 가벼운 이슈용이라, 위의 이어 쓰기 기준(12만)을 쓰지 않는다.

| 항목 | 값 | 근거 |
|---|---|---|
| 아끼는 것 | 단계마다 새 세션의 첫 호출 4.3만~10만 | 위 "조건과 근거"의 새 세션 시작 문맥 실측. 일반 실행은 가벼운 변경도 설계, 구현, 리뷰, 통합, 배포, 검증으로 세션을 여러 번 연다 |
| 더 내는 것 | 호출마다 0.1 × (지금 문맥 − 새 세션 시작 문맥) | 위와 같다 |
| 넘기는 기준 | 정해진 자리에서 `dobby_v2_ctx_growth`(이 세션 첫 호출 뒤로 늘어난 문맥)가 `DOBBY_LIGHT_MAX_GROWTH`(30만)를 넘으면 새 세션이 light 로 잇는다. 리뷰는 기준과 상관없이 늘 별도 세션이다 | 대화형 세션은 시작 문맥이 8.8만~11.4만이라(2026-11-20 세션 40개 실측) 전체 크기로 재면 시작하자마자 12만에 닿는다. FE1-2770 은 첫 호출 11만 3,607에서 시작해 늘어난 양 5만 3천으로 구현 끝에서 넘어갔다. 새 세션은 사람이 다시 입력해야 하고 시작 문맥을 다시 읽어 느리다 |
| 기다림 | `dobby_v2_wait` 가 셸 안에서 30초마다 확인한다. 모델 호출은 최대 8분에 한 번이다 | 세션이 30초마다 깨어나면 그때마다 문맥 전체를 다시 읽는다 |

light 로 아낀 양은 아직 재지 않았다. 위 표는 기존 실측값으로 세운 기준이다. 실제 light 오더가 쌓이면 세션 기록으로 다시 잰다.
