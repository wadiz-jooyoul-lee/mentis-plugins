# 주간회의 완료 항목 요약 아티팩트 (dobby-weekly-report-summary)

FE개발1 주간 회의 페이지에서 **내 완료 항목**을 이슈마다 쉽게 풀어 쓴 아티팩트로 만든다.

진행 순서: Step 0 → Step 1 → Step 2 → Step 3 → Step 4 → Step 5.

## 고정 상수

| 항목 | 값 |
| --- | --- |
| 회의 페이지 부모 | `17865081256` (WadizDev 스페이스 「FE 1」) |
| 회의 페이지 제목 형식 | `[FE개발1] 주간 회의 YYYY-MM-DD` |
| 대상 행 | 「개인 공유」 표에서 이름 칸이 내 이름인 행의 **완료** 부분 |
| 이슈 결과 문서 | `$ORCHESTRATION_META/{이슈키}/outcome.md` |
| 검증 기록 | `$ORCHESTRATION_META/{이슈키}/test-runs/{시각}/result.md` (가장 최근 회차) |
| 아티팩트 틀 | 이 스킬 폴더의 `references/template.html` |
| 아티팩트 제목 | `{회의 날짜} 주간회의` (예: `2026-11-17 주간회의`) |

## Step 0. 설정과 내 이름

1. `${CLAUDE_PLUGIN_ROOT}/reference/config.md` 의 "설정 절차"를 그대로 따른다. config.env 는 **읽기만** 한다. 이하 메타 경로는 `$ORCHESTRATION_META` 기준이다.
2. 내 이름을 얻는다. `twg` 는 `--output-file` 을 붙여야 JSON 으로 읽을 수 있다.
   ```bash
   W=$(mktemp -d)
   twg whoami -o json --output-file $W/who.json
   ME=$(jq -r '.data.name' $W/who.json)
   ```
   이 이름이 회의 페이지 표의 이름 칸과 같은지 Step 2 에서 맞춰 본다.

## Step 1. 회의 페이지 찾기

1. `mcp__mcp-atlassian__confluence_get_page_children`(parent_id `17865081256`, limit 50)으로 하위 페이지를 조회한다. 50건이 꽉 차면 `start` 로 다음 쪽까지 모두 본다.
2. 제목에서 `YYYY-MM-DD` 날짜를 읽는다. 날짜가 없는 제목(예: `[FE개발1] 주간 회의 템플릿`)은 뺀다.
3. 페이지를 고른다.
   - 인자로 날짜를 받았으면 그 날짜의 페이지를 쓴다.
   - 인자가 없으면 `date +%Y-%m-%d` 의 오늘 날짜 **이상**인 날짜 중 가장 이른 페이지를 쓴다. **오늘 날짜도 포함한다.**
4. 해당 페이지가 없으면 "오늘 이후 회의 페이지가 없습니다"라고 알리고 **스킬을 종료한다.** 지난 페이지로 대신하지 않는다.

## Step 2. 완료 항목 뽑기

1. `mcp__mcp-atlassian__confluence_get_page`(page_id, include_metadata false)로 본문을 읽는다.
2. 「개인 공유」 표에서 이름 칸이 `$ME` 인 행의 업무 칸을 찾는다. 그 행이 없으면 찾은 이름과 표의 이름 목록을 보여 주고 종료한다.
3. 업무 칸에서 **완료** 와 **진행 중** 사이의 부분만 쓴다.
4. 배포일 소제목(예: `11-17 배포`, `11-12 배포`, `배포 정보 없음`)과 그 아래 이슈 키를 함께 뽑는다. 한 줄에 `/` 로 묶인 이슈 키는 모두 뽑는다.
5. 뽑은 목록을 표(배포일, 이슈키, 회의 페이지의 한 줄 설명)로 보여 주고 바로 Step 3 으로 간다.

## Step 3. 이슈별 근거 읽기

이슈마다 아래 순서로 읽는다. 근거에 없는 내용은 쓰지 않는다.

1. `outcome.md` 결과 문서 전체. 문서 아래 "후속" 절이 앞 절의 내용을 바꿨으면 **최종 상태**로 쓴다.
2. 가장 최근 검증 회차 `result.md` 에서 요약 줄과 통과 결과(환경, 시험 수, 확인한 화면이나 프로젝트 번호).
3. 원인 설명이 결과 문서에 부족하면 같은 폴더의 `explainer.md` 를 읽는다.
4. 메타 폴더가 없는 이슈만 Jira 이슈(summary, status, description)를 읽는다.

## Step 4. 아티팩트 만들기

1. `references/template.html` 에서 `<title>` 다음 줄부터 `</style>` 까지를 그대로 가져온다. 스타일은 고치지 않는다.
2. 본문은 새로 쓴다. 틀 파일의 본문 구조를 따른다.
   - 왼쪽 목차(`nav.toc`): 한눈에 보기, 주제 묶음 이름, 이슈 번호 뒤 4자리와 짧은 제목.
   - 머리말: `{날짜} 주간회의` 제목, 완료 이슈 수, 업무 기간(회의 페이지 상단 문구 기준).
   - 한눈에 보기 표: 이슈, 핵심 한 줄, 배포일.
   - 주제별 묶음(`section.group`)과 이슈 카드(`article.item`). 비슷한 이슈끼리 묶는다(예: 버그, 화면 개선, 데이터 수집, 옛 코드 정리).
   - 카드 내용: 배포일과 화면 배지, 제목, 핵심 한 줄, 이전과 지금 비교(`.ba`), 필요하면 표나 목록, 고친 파일 경로(`.where`), 확인한 검증 결과(`.note`).
   - 꼬리말: 근거 문서 종류.
3. 파일은 세션의 scratchpad 폴더에 `weekly-{날짜}.html` 로 저장한다.
4. `Artifact` 도구로 게시한다. icon 은 `calendar`, description 은 한 문장이다.
5. 게시 링크와 담은 이슈 표를 보고한다. 아티팩트는 비공개이며 공유는 사용자가 페이지의 공유 메뉴에서 한다고 알린다.

## Step 5. 후속 수정

- 같은 세션에서 수정 요청을 받으면 같은 파일을 고쳐 **같은 파일 경로로 다시 게시**한다(주소 유지).
- 목차 굵게 표시, 화면 모형, 에픽 진행률, 삭제 검토 같은 꾸밈은 요청이 있을 때만 넣는다. 기본에는 넣지 않는다.

## 주의

- Confluence 페이지와 Jira 이슈는 **읽기만** 한다. 상태 변경, 코멘트, 페이지 수정을 하지 않는다.
- 쉬운 말로 쓴다. 한 문장은 짧게 끊는다. 전문용어와 영문 약어는 처음 나올 때 괄호로 뜻을 적는다.
- 옛 이름이나 작업 이력보다 **최종 결과**를 쓴다.
- 도구 이야기(이 플러그인, 대시보드, 메타 파일 이름, 차수 리뷰 표기, 에이전트 이름)는 본문에 쓰지 않는다. 읽는 사람은 이 도구를 쓰지 않는다.
- 모든 진행 서술과 사용자 안내는 한국어와 존댓말로 한다.
