# 기기 시험 — wadiz-android 오더

안드로이드 오더는 배포하지 않는다. 작업 폴더를 이 컴퓨터에서 디버그로 빌드해 **연결된 기기**에 설치하고, rc4 서버로 시험한다. 디버그 빌드는 처음 설치하면 rc4 를 본다(`build-config` 의 `SERVER_MODE`).

이 문서는 검증 스킬 2절(테스트 목록 확보)부터를 대신한다. 브라우저와 PR 머지, 웹 배포 반영 확인은 하지 않는다. 판정 어휘와 보류 기준, 근거 칸 규칙, result.md 틀은 검증 스킬 본문과 같다.

## 두 가지 실행

| 실행 | 언제 | 도는 시나리오 | 회차 열기 |
|---|---|---|---|
| 직접 실행 | 사람이 `/dobby-test {키}` 를 쳤을 때 | 테스트 계획의 시나리오 전부 | `dobby_testrun_new {키} {전체 시나리오 수} '로컬 기기 (rc4)' {시험 커밋}` |
| 묶음 실행 | 전체 실행 중 `/do` 검증 세션이 `묶음=… 시나리오=…` 를 넘겼을 때 | 받은 번호만 | `dobby_testrun_current {키} {전체 시나리오 수} '로컬 기기 (rc4)' {시험 커밋}` |

- 시험 커밋은 `git -C {작업 폴더} rev-parse HEAD` 다. 작업 폴더는 상태 문서 작업 폴더 표의 `wadiz-android` 행이다.
- 테스트 계획(test-plan.md)이 없으면 시험하지 않는다. "테스트 계획이 없습니다. /do {키} 로 설계부터 해 주세요"라고 알리고 끝낸다.
- 묶음 실행은 테스트 계획 전체를 읽지 않고 `dobby_testplan_slice {키} {번호들}` 이 내는 부분만 읽는다.
- 기기는 한 대라 묶음을 함께 돌리지 않는다.

## 하는 일

1. **회차 열기**: 위 표대로 연다. 묶음 실행이면 열린 회차가 있을 때 그 폴더가 나온다.
2. **설치 (회차를 새로 열었을 때만)**: `dobby_android_install {키} {작업 폴더}`. 열린 회차를 잇는 묶음은 같은 커밋이 이미 깔려 있으므로 건너뛴다.

   | 반환 | 뜻 | 할 일 |
   |---|---|---|
   | 0 | 설치됨 | 출력의 `기기:` 줄(모델, 앱 버전, 서버, 시험 커밋)을 result.md 머리 `(진행 중)` 자리에 옮긴다 |
   | 1 | 앱 빌드 실패 | 코드 결함이다. 이번에 돌 시나리오를 모두 `FAIL` 로, 근거에 출력된 원인 줄을 적고 4번 마감을 한다 |
   | 2 | JDK·SDK 없음 | 출력 줄을 사람에게 알리고 끝낸다. 묶음 실행이면 그 줄을 `막힘` 이유로 남긴다. 헬퍼가 JDK 17 을 먼저 고른다(리액트 네이티브 모듈 굽기가 17 을 요구한다) |
   | 3 | 기기 없음 또는 허용 대기 | 사람만 할 수 있는 일이다. 출력 줄(연결해 달라는 말, 또는 휴대폰에서 「USB 디버깅 허용」을 눌러 달라는 말)을 그대로 알린다. 묶음 실행이면 `ask.md` 대로 질문을 남긴다 |
   | 4 | 앱 빌드 권한 없음 | 같은 방법으로 "`gh auth refresh -h github.com -s read:packages` 를 한 번 실행해 주세요"라고 알린다 |

   - 굽기와 설치는 처음 빌드하는 폴더면 15분 넘게 걸린다(실측 FE1-2771: 굽기 13분 34초, 설치 16분 58초). **처음부터 뒤에서 돌린다**(백그라운드 실행). 기다리는 동안에는 `dobby_android_progress {키}` 의 한 줄(작업 수, 컴파일한 모듈 수, 마지막 작업)로 진행을 알린다.
   - **로그인 (회차를 새로 열었을 때 한 번)**: `dobby_android_login`. 기기에 남은 계정을 믿지 않고 로그아웃한 뒤 시험 계정(`TEST_LOGIN_ID`)으로 다시 로그인한다. 출력 줄을 result.md 머리 `- **로그인**:` 에 옮긴다. 반환 1 이면 출력 줄을 근거로 로그인이 필요한 시나리오를 `SKIP(환경)` 으로 적는다.
   - **실험군**: 테스트 계획의 `- **실험군**:` 줄이 있는 시나리오는 그 앞에서 `dobby_android_ab_pin {실험키} {군}` 으로 지정하고, 회차를 마감하기 전에 원래 군(계획에 적힌 값)으로 되돌린다. 지정과 되돌림을 result.md 머리에 적는다.

3. **시나리오마다** (직접 실행은 전부, 묶음 실행은 받은 번호만):
   1. `adb logcat -c` 로 기기 로그를 비운다.
   2. **진입**: 계획의 진입 칸대로 한다. 링크면 `adb -s {기기} shell am start -W -a android.intent.action.VIEW -d '{주소}' com.markmount.wadiz`, 앱 첫 화면이면 `dobby_android_launch`. ⛔ `monkey` 로 띄우지 않는다 — 디버그 빌드에는 실행 화면이 둘(앱, LeakCanary)이라 무작위로 메모리 점검 화면이 열린다.
   3. **조작**: 목록의 카드처럼 밀어야 보이는 요소는 `dobby_android_tap_id {아이디}` 로 누른다. 머리말과 하단 탭을 피한 자리로 밀어 맞춘 뒤 누른다(화면 위쪽 카드를 바로 누르면 검색창이 눌려 결과를 잃는다). 그 밖의 누를 곳은 `dobby_android_ui [{글자나 testTag}]` 로 찾는다(마지막 칸이 좌표). 누르기 `adb -s {기기} shell input tap {x} {y}`, 글자 넣기 `input text '{글자}'`(영문과 숫자만 된다), 위로 밀기 `input swipe 540 1600 540 600 300`, 뒤로 `input keyevent 4`. 덤프 원문(`uiautomator dump` 를 직접)은 부르지 않는다.
   4. **로그인**: 회차 시작 때 `dobby_android_login` 으로 맞췄다. 시나리오 도중 로그인이 풀렸으면 다시 부른다.
   5. **확인**: 화면 글자와 아이디는 `dobby_android_ui`, 서버 응답은 `dobby_android_log api`, 강제 종료는 `dobby_android_log crash`(빈 출력이어야 한다. 강제 종료만 모이는 기록을 본다). 웹뷰 화면도 글자 대부분이 화면 요소로 보인다. 안 보이면 갈무리로 본다.
   6. **기록**: result.md 의 그 행에 실제값, 판정, 근거를 채우고 `dobby_testrun_update {키} {폴더시각} 테스트중 {성공}/{실패}/{skip}` 로 집계를 바로 반영한다.
      - 근거 칸에는 **관측한 사실**(화면 글자, 응답 일부, 로그 줄)을 적는다. 파일 이름만 적지 않는다.
      - 화면을 꼭 보여야 하면 `dobby_android_shot {결과폴더} s{번호}-{단계}` 로 남기고 본문에 `![S{번호} {단계}단계 — {무엇을 보라는 것인지}](파일.webp)` 로 띄운다.
   - 판정 어휘와 보류 기준은 검증 스킬 6-1 과 같다. 실제 결제나 발송처럼 되돌릴 수 없는 일은 `SKIP(위험)`, 기기 밖 조작(구글 계정 선택창, 외부 결제창)은 `SKIP(환경)` 이다.
   - `[수집]` 시나리오는 기기 로그에서 그 이벤트 이름으로 찾는다(`dobby_android_log '{이벤트 이름}'`). 로그에 남지 않는 수집이면 `SKIP(환경)` 과 그 사유를 적는다. 빼지 않는다.
4. **마감**: 직접 실행은 시나리오를 다 돈 뒤 마감한다. 묶음 실행은 `dobby_verify_next {키}` 가 `done` 일 때만 마감하고, 묶음이 남았으면 마감하지 않고 끝낸다.
   1. result.md 를 "한눈 요약 → 실패 상세 → 전체 표" 순으로 정리한다.
   2. `{결과폴더}/summary.html` 을 쓴다(7절의 화면 출력 틀을 HTML 로).
   3. `dobby_testrun_update {키} {폴더시각} {완료|완료(이슈 있음)} {성공}/{실패}/{skip}`.
   4. `dobby_testrun_lint {결과폴더}` — 거부되면 고쳐서 다시 부른다.
   5. `dobby_testrun_prune {결과폴더}`.
   6. 실험군을 바꿨으면 원래 군으로 되돌렸는지 본다(`dobby_android_ab_pin {실험키} {원래 군}`).
   7. `dobby_gradle_daemon_cleanup {키}` — 이 회차의 빌드가 띄운 그래들 데몬만 끈다. 저장소마다 메모리 설정이 달라 서로 재사용되지 않고, 3시간 동안 4~6GB 씩 남는다.
   8. `dobby_unit_end {키} test "검증 통과 N · 실패 M · 보류 K"`.
   - 배포 표는 없으므로 `dobby_ship_stage` 는 부르지 않는다.

## 정리

- adb 연결과 포트 연결(`adb forward`)은 끊지 않는다. 앱도 지우지 않는다.
- 갈무리 외의 임시 파일을 남기지 않는다.

## 리액트 네이티브 모듈이 있는 오더

작업 폴더 표에 `wadiz-multiplatform` 이 있으면 위 절차에서 아래만 바꾼다. 나머지는 같다.

- **앱 폴더**: 위의 "작업 폴더"는 `dobby_rn_host {키}` 가 낸 경로다. wadiz-android 도 고친 오더면 그 작업 폴더가, 모듈만 고친 오더면 시험 전용 앱 폴더가 나온다. 시험 전용 폴더는 커밋하지 않는다. 반환 2(앱 라인을 정하지 못함)면 출력 줄을 사람에게 묻고 끝낸다.
- **시험 커밋**: `git -C {모듈 작업 폴더} rev-parse HEAD` 다.
- **2. 설치**를 아래로 바꾼다. 출력 줄은 기록 칸에 옮기고, `리액트 네이티브 출처:` 줄은 result.md 머리 `기기:` 줄 아래에 둔다.
  1. `dobby_rn_mode {키} {앱 폴더}` 로 실을 방법을 정한다.
  2. `metro` 면:
     1. `dobby_rn_metro start {키}` 가 포트 번호를 낸다(기기 연결과 포트 잇기까지 한다).
     2. `dobby_rn_devserver apply {앱 폴더} {포트}` 로 앱 시작 코드에 Metro 주소 한 줄을 넣는다.
     3. `dobby_android_install {키} {앱 폴더}` 로 설치한다.
     4. 설치 결과와 상관없이 **바로** `dobby_rn_devserver revert {앱 폴더}` 로 그 줄을 뺀다.
  3. `bake` 면:
     1. `dobby_rn_bake {키}` 로 모듈을 굽는다. 실패(반환 1)는 코드 결함이다. 이번 시나리오를 모두 `FAIL` 로, 근거에 출력된 원인 줄을 적고 마감한다.
     2. `dobby_android_install {키} {앱 폴더} -PrnLocal={모듈 작업 폴더}` 로 설치한다.
  - 열린 회차를 잇는 묶음은 설치를 건너뛴다. `metro` 면 `dobby_rn_metro start {키}` 만 다시 부른다. 살아 있으면 그대로 이어 쓰고, 꺼졌으면 다시 띄운다.
- **확인**: 수집 이벤트, 서버 요청, 찜·알림 토글은 `dobby_android_log rn-e2e` 로 본다. 상품 카드 수집(`ecommerce`)은 줄 앞에 `{목록 이름}/{종류} {상품 번호}`(예: `검색_결과_회귀_유사추천_펀딩/impression 407113`)가 붙어 계획의 기대값과 바로 맞춰 볼 수 있다. 테스트 계획의 기대값(`PV:SEARCH` 같은 문법)과 `포트 | 함수 | 인자` 줄을 맞춰 보고, 맞는 줄을 근거 칸에 옮긴다. 리액트 네이티브 화면 요소는 `dobby_android_ui {testID}` 로 찾는다.
- **굽기 재확인**: `metro` 로 시험한 회차는 마감(4번) 바로 앞에서, 그 회차의 시나리오가 모두 통과했을 때만 한다. 실패가 있으면 하지 않는다.
  1. `dobby_rn_metro stop {키}`.
  2. 위 `bake` 순서대로 굽고 설치한다.
  3. 테스트 계획에서 제목에 `[굽기 재확인]` 이 붙은 시나리오만 다시 돈다.
  4. 결과는 그 행의 근거 칸 끝에 `굽기 재확인: 통과 — {관측한 사실}` 로 덧붙인다. 실패하면 그 행을 `FAIL` 로 바꾸고 근거에 `Metro 통과, 구운 빌드에서 실패 — {관측한 사실}` 로 적은 뒤 집계를 다시 반영한다.
  5. `리액트 네이티브 출처:` 줄 끝에 `+ 굽기 재확인(0.0.0-dev, 모듈 커밋 {짧은 커밋})` 을 덧붙인다.
- **정리**: 마감 뒤 `dobby_rn_metro stop {키}` 와 `dobby_rn_host_release {키}` 를 부른다. Metro 로 시험한 회차가 실패로 끝나 굽기 재확인을 하지 않았으면, 기기의 앱은 Metro 를 보는 빌드로 남아 Metro 를 끈 뒤에는 리액트 네이티브 화면이 열리지 않는다. result.md 한눈 요약에 그 사실을 한 줄 적는다. 묶음이 남아 마감하지 않고 끝나는 세션은 둘 다 부르지 않는다. adb 연결과 포트 잇기(`adb reverse`)는 끊지 않는다.
