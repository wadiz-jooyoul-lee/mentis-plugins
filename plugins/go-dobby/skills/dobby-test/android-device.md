# 기기 시험 — wadiz-android 오더

안드로이드 오더는 배포하지 않는다. 작업 폴더를 이 컴퓨터에서 디버그로 빌드해 **연결된 기기**에 설치하고, rc4 서버로 시험한다. 디버그 빌드는 처음 설치하면 rc4 를 본다(`build-config` 의 `SERVER_MODE`).

이 문서는 검증 스킬 2절(테스트 목록 확보)부터를 대신한다. 브라우저와 PR 머지, 웹 배포 반영 확인은 하지 않는다. 판정 어휘와 보류 기준, 근거 칸 규칙, result.md 틀은 검증 스킬 본문과 같다.

## 두 가지 실행

| 실행 | 언제 | 도는 시나리오 | 회차 열기 |
|---|---|---|---|
| 직접 실행 | 사람이 `/dobby-test {키}` 를 쳤을 때 | 테스트 계획의 시나리오 전부 | `dobby_testrun_new {키} {전체 시나리오 수} '로컬 기기 (rc4)' {시험 커밋}` |
| 묶음 실행 | 전체 실행 중 `/do` 검증 세션이 `묶음=… 시나리오=…` 를 넘겼을 때 | 받은 번호만 | `dobby_testrun_current {키} {전체 시나리오 수} '로컬 기기 (rc4)' {시험 커밋}` |

- 시험 커밋은 `git -C {작업 폴더} rev-parse HEAD` 다. 작업 폴더는 상태 문서 작업 폴더 표의 `wadiz-android` 행이다.
- 테스트 계획(test-plan.md)이 없으면 시험하지 않는다. "테스트 계획이 없습니다. /do {키} 로 설계부터 해 주세요"라고 알리고 끝낸다.
- 묶음 실행은 테스트 계획 전체를 읽지 않고 `dobby_testplan_slice {키} {번호들}` 이 내는 부분만 읽는다.
- 기기는 한 대라 묶음을 함께 돌리지 않는다.

## 하는 일

1. **회차 열기**: 위 표대로 연다. 묶음 실행이면 열린 회차가 있을 때 그 폴더가 나온다.
2. **설치 (회차를 새로 열었을 때만)**: `dobby_android_install {키} {작업 폴더}`. 열린 회차를 잇는 묶음은 같은 커밋이 이미 깔려 있으므로 건너뛴다.

   | 반환 | 뜻 | 할 일 |
   |---|---|---|
   | 0 | 설치됨 | 출력의 `기기:` 줄(모델, 앱 버전, 서버, 시험 커밋)을 result.md 머리 `(진행 중)` 자리에 옮긴다 |
   | 1 | 앱 빌드 실패 | 코드 결함이다. 이번에 돌 시나리오를 모두 `FAIL` 로, 근거에 출력된 원인 줄을 적고 4번 마감을 한다 |
   | 2 | JDK·SDK 없음 | 출력 줄을 사람에게 알리고 끝낸다. 묶음 실행이면 그 줄을 `막힘` 이유로 남긴다 |
   | 3 | 기기 없음 | 사람만 할 수 있는 일이다. "USB 디버깅을 켠 기기를 연결해 주세요"라고 알린다. 묶음 실행이면 `ask.md` 대로 질문을 남긴다 |
   | 4 | 앱 빌드 권한 없음 | 같은 방법으로 "`gh auth refresh -h github.com -s read:packages` 를 한 번 실행해 주세요"라고 알린다 |

3. **시나리오마다** (직접 실행은 전부, 묶음 실행은 받은 번호만):
   1. `adb logcat -c` 로 기기 로그를 비운다.
   2. **진입**: 계획의 진입 칸대로 한다. 링크면 `adb -s {기기} shell am start -W -a android.intent.action.VIEW -d '{주소}' com.markmount.wadiz`, 앱 첫 화면이면 `adb -s {기기} shell monkey -p com.markmount.wadiz 1`.
   3. **조작**: 누를 곳은 `dobby_android_ui [{글자나 testTag}]` 로 찾는다(마지막 칸이 좌표). 누르기 `adb -s {기기} shell input tap {x} {y}`, 글자 넣기 `input text '{글자}'`, 위로 밀기 `input swipe 540 1600 540 600 300`, 뒤로 `input keyevent 4`. 덤프 원문(`uiautomator dump` 를 직접)은 부르지 않는다.
   4. **로그인**: 필요한 시나리오면 먼저 화면에서 로그인 상태를 본다. 앱 데이터를 지웠거나 로그아웃 상태면 계획의 계정으로 로그인한다. 비밀번호는 config.env 의 `TEST_LOGIN_PW` 다.
   5. **확인**: 화면 글자와 아이디는 `dobby_android_ui`, 서버 응답은 `dobby_android_log api`, 강제 종료는 `dobby_android_log crash`(빈 출력이어야 한다). 웹뷰 화면도 글자 대부분이 화면 요소로 보인다. 안 보이면 갈무리로 본다.
   6. **기록**: result.md 의 그 행에 실제값, 판정, 근거를 채우고 `dobby_testrun_update {키} {폴더시각} 테스트중 {성공}/{실패}/{skip}` 로 집계를 바로 반영한다.
      - 근거 칸에는 **관측한 사실**(화면 글자, 응답 일부, 로그 줄)을 적는다. 파일 이름만 적지 않는다.
      - 화면을 꼭 보여야 하면 `dobby_android_shot {결과폴더} s{번호}-{단계}` 로 남기고 본문에 `![S{번호} {단계}단계 — {무엇을 보라는 것인지}](파일.webp)` 로 띄운다.
   - 판정 어휘와 보류 기준은 검증 스킬 6-1 과 같다. 실제 결제나 발송처럼 되돌릴 수 없는 일은 `SKIP(위험)`, 기기 밖 조작(구글 계정 선택창, 외부 결제창)은 `SKIP(환경)` 이다.
   - `[수집]` 시나리오는 기기 로그에서 그 이벤트 이름으로 찾는다(`dobby_android_log '{이벤트 이름}'`). 로그에 남지 않는 수집이면 `SKIP(환경)` 과 그 사유를 적는다. 빼지 않는다.
4. **마감**: 직접 실행은 시나리오를 다 돈 뒤 마감한다. 묶음 실행은 `dobby_verify_next {키}` 가 `done` 일 때만 마감하고, 묶음이 남았으면 마감하지 않고 끝낸다.
   1. result.md 를 "한눈 요약 → 실패 상세 → 전체 표" 순으로 정리한다.
   2. `{결과폴더}/summary.html` 을 쓴다(7절의 화면 출력 틀을 HTML 로).
   3. `dobby_testrun_update {키} {폴더시각} {완료|완료(이슈 있음)} {성공}/{실패}/{skip}`.
   4. `dobby_testrun_lint {결과폴더}` — 거부되면 고쳐서 다시 부른다.
   5. `dobby_testrun_prune {결과폴더}`.
   6. `dobby_unit_end {키} test "검증 통과 N · 실패 M · 보류 K"`.
   - 배포 표는 없으므로 `dobby_ship_stage` 는 부르지 않는다.

## 정리

- adb 연결과 포트 연결(`adb forward`)은 끊지 않는다. 앱도 지우지 않는다.
- 갈무리 외의 임시 파일을 남기지 않는다.
