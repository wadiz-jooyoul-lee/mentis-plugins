# QA 앱 시험 — 출시 브랜치에 머지돼 QA 로 배포된 앱 (`/dobby-test {키} qa`)

앱 오더가 출시 브랜치에 머지되면 QA 배포 작업이 Firebase App Distribution 으로 QA 앱을 내보낸다. 이 문서는 그 **배포된 앱**으로 테스트 계획을 다시 돈다. 로컬 기기 시험(`android-device.md`)과 다른 점은 셋이다.

- 빌드하지 않는다. 사람이 Firebase App Tester 로 깐 앱을 쓰고, 이 스킬은 버전이 맞는지만 본다.
- 리액트 네이티브 시험 기록(`[rn-e2e]`)이 나오지 않는다. 배포용 모듈은 디버그가 아니라 기록을 켜지 않는다(모듈 `src/app/bootstrap.ts` 의 `enableE2eLog(NativeRnRuntime.isDebugBuild())`).
- iOS 는 이 컴퓨터에서 깔거나 조작할 수 없다. 사람이 볼 점검표를 만들고 답을 받아 적는다.

대신 앱 쪽 기록 두 가지가 QA 앱에서도 나온다. 기록 조건이 앱 빌드 설정(`com.wadiz.buildconfig.BuildConfig.DEBUG`)을 보는데 QA 빌드에서 참이기 때문이다(실측 FE1-2771 QA 앱 26.48.0.8).

- **서버 요청**: `dobby_android_log api`. 리액트 네이티브 화면의 요청도 같은 통신 장치(`RnApiProvider`)를 거쳐 `--> GET https://…`, `<-- 200 https://…` 줄로 남는다.
- **수집**: `dobby_android_log TC_TRACK`. 앱 공용 수집 기록이 `TC_TRACK: event=ecommerce name=view_item_list listId={목록 이름} itemId={번호}` 처럼 남는다.

이 문서는 검증 스킬 2절(테스트 목록 확보)부터를 대신한다. 판정 어휘, 근거 칸 규칙, result.md 틀은 검증 스킬 본문과 같고, 기기 조작 방법은 `android-device.md` 3번(시나리오마다)과 같다. 묶음 실행은 없다. 사람이 직접 친 실행만 받는다.

## 하는 일

1. **시작 조건**
   - 테스트 계획(test-plan.md)이 없으면 "테스트 계획이 없습니다"라고 알리고 끝낸다.
   - 상태 문서 `## 앱 출시` 표에서 앱 저장소 행(wadiz-android, wadiz-ios)의 단계와 버전을 읽는다. wadiz-android 행이 `QA 배포 확인` 이 아니면 2번 도우미가 반환 4 로 알려 준다.
   - 작업 폴더 표에 wadiz-android 가 없으면(iOS 만 고친 오더) 2~5번을 건너뛰고 6번 점검표만 한다. 회차는 열지 않고 점검 결과를 사람에게 보여 준 뒤 끝낸다.
2. **앱 확인**: `dobby_android_qa_check {키}`.

   | 반환 | 뜻 | 할 일 |
   |---|---|---|
   | 0 | QA 배포본이 깔려 있고 서버가 rc4 | 출력의 `기기:` 줄과 `서버:` 줄을 result.md 머리에 옮긴다 |
   | 1 | 앱 없음, 버전 다름, 로컬 빌드가 깔림 | 출력 줄을 그대로 알리고 끝낸다. 디버그 빌드와 QA 앱은 서명이 달라 덮어 깔리지 않으므로, 로컬 빌드가 깔려 있으면 지우고 깔아 달라고 한다 |
   | 2 | 서버가 rc4 가 아님 | 출력 줄을 그대로 알리고 끝낸다 |
   | 3 | 기기 없음 또는 허용 대기 | 출력 줄을 그대로 알리고 끝낸다 |
   | 4 | QA 배포 확인 전 | 출력 줄을 그대로 알리고 끝낸다 |

3. **회차 열기**: `dobby_testrun_new {키} {전체 시나리오 수} 'QA 앱 {버전} (rc4)' {시험 커밋}`.
   - 버전은 `## 앱 출시` 표 wadiz-android 행의 버전이다.
   - 시험 커밋은 그 행 PR 의 머지 커밋이다: `gh pr view {번호} -R wadiz-app/wadiz-android --json mergeCommit -q .mergeCommit.oid`.
   - result.md 머리에 `- **앱**: QA 배포본 {버전} (App Tester 설치)` 한 줄을 둔다.
4. **로그인과 실험군**: `android-device.md` 2번의 로그인, 실험군 줄과 같다(`dobby_android_login`, `dobby_android_ab_pin`). QA 앱에도 개발자 메뉴가 있다(QA 빌드는 디버그 소스 폴더를 쓴다).
5. **시나리오마다**: `android-device.md` 3번대로 진입, 조작, 확인, 기록을 한다. 통과 기준은 아래 표대로 판정한다.

   | 계획의 통과 기준 | QA 앱에서 |
   |---|---|
   | 화면 요소, 글자, 갈무리 | 그대로 본다(`dobby_android_ui`, `dobby_android_shot`) |
   | 서버 요청 `HTTP:GET {주소} [인자]` | `dobby_android_log api` 에서 `--> GET` 줄의 주소와 인자를 찾는다 |
   | 상품 카드 수집 `{목록 이름}/impression`, `/click` | `dobby_android_log TC_TRACK` 에서 노출은 `name=view_item_list listId={목록 이름}`, 클릭은 `name=select_item listId={목록 이름}` 줄을 찾는다 |
   | 화면 진입 `PV:{화면}` | `TC_TRACK: event=pv url={주소}` 줄의 주소로 본다 |
   | 그 밖에 시험 기록에만 나오는 것(포트 호출 등) | 보류한다. 아래 「보류 적는 법」 |
   | 기록 부정 기준(`!…` — 나오지 않아야 함) | 아래 「부정 기준 보는 법」 |

   - **부정 기준 보는 법**: 시험 기록은 리액트 네이티브 화면이 보낸 것만 담지만, 앱 기록에는 **앱 전체의 요청과 수집이 섞인다.** 걸린 줄이 있으면 바로 실패로 보지 않고, 그 시각에 떠 있던 화면을 가린다. 화면 이동은 `moveToNativePage {주소}` 줄과 `TC_TRACK: event=pv … screen={화면}` 줄로 본다. 시험 대상 화면이 떠 있을 때 나간 것만 실패다. 다른 화면이 부른 것이면 부르는 코드를 찾아 근거 칸에 시각과 함께 적는다. 예: FE1-2771 의 옛 추천 주소 `/recommendation/item` 은 상세 화면이 떠 있는 동안 홈의 최근 본 상품 추천(`RecentRelatedUseCase`)이 불렀다.
   - 한 시나리오의 기준 중 하나라도 보류면 그 시나리오는 `SKIP(환경)` 이다. 판정한 기준은 근거 칸에 그대로 적어 둔다.
   - **보류 적는 법**: 근거 칸에 `QA 앱은 시험 기록이 꺼져 판정 불가 — 디버그 회차 {회차 폴더 시각} 에서 통과` 처럼 적는다. 디버그 회차는 상태 문서 `## 테스트 실행 이력` 에서 같은 시나리오가 통과한 마지막 회차다. 없으면 `디버그 회차 통과 기록 없음` 으로 적는다.
6. **iOS 점검표**: 작업 폴더 표에 wadiz-ios 가 있을 때만 한다.
   - `## 앱 출시` 표 wadiz-ios 행이 `QA 배포 확인` 이 아니면 result.md 에 `- **iOS**: QA 배포 확인 전이라 점검하지 않음` 한 줄만 둔다.
   - 맞으면 테스트 계획에서 **화면으로 볼 수 있는 기준만** 뽑아 점검표를 만들어 사람에게 보여 준다. 각 줄은 시나리오 번호, 조작, 볼 것으로 쓴다. 맨 위에 "Firebase App Tester 로 iOS {버전}을 깔고 서버를 rc4 로 맞춘 뒤 봐 주세요"를 둔다.
   - 사람의 답을 result.md `## iOS 점검` 절에 시나리오마다 `통과`, `실패 — {사람이 본 것}`, `보지 않음` 으로 적는다. 사람이 답하지 않고 넘기면 절 머리에 `답 없음` 을 적고 마감한다. iOS 점검은 회차 집계(성공/실패/skip)에 넣지 않는다.
7. **마감**: `android-device.md` 4번의 1~6과 8을 한다. 7(그래들 데몬 정리)은 빌드를 하지 않았으므로 하지 않는다.
   - `## 앱 출시` 표는 바꾸지 않는다. 다음 할 일이 그 표의 끝 단계로 해결 차례를 정하기 때문이다. QA 시험 결과는 회차 기록(테스트 실행 이력)으로만 남는다.

## 정리

- 앱을 지우지 않는다. adb 연결과 포트 연결은 끊지 않는다.
- 갈무리 외의 임시 파일을 남기지 않는다.
