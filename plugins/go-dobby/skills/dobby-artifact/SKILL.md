# dobby-artifact

**이번 세션에서 한 일**을 사용자가 말한 요구사항에 맞춰 글로 써서 공개 아티팩트로 게시한다.

```
/dobby-artifact {요구사항}
   → 세션에서 한 일 모으기 → 담을 내용 확인받기 → 원고 작성
   → 금지어 자동 검사(스스로 고쳐 재검사) → 게시 → 링크 보고
```

## dobby-share와 헷갈리지 마라

| | dobby-share | **dobby-artifact(이 스킬)** |
|---|---|---|
| 근거 | 이미 있는 `outcome.md`·`explainer.md` | **이번 세션에서 실제로 한 일** |
| 하는 일 | 그 문서를 HTML로 **옮긴다** | 요구사항에 맞춰 **새로 쓴다** |
| 근거가 없으면 | "먼저 만들어라"하고 중단 | 세션에 한 일이 없으면 중단 |

문서가 이미 있고 그걸 그대로 공유하려는 것이면 **dobby-share를 쓴다.**

## 설정 (첫 실행 시 확인)
작업 시작 전 **`${CLAUDE_PLUGIN_ROOT}/reference/config.md`의 "설정 절차"를 그대로 따른다**: `~/.config/go-dobby/config.env`를 source 해 환경 변수를 **읽기만** 한다(config.env 없으면 `/dobby-init` 먼저). 이하 메타 경로는 `$ORCHESTRATION_META` 기준.

## 입력

```
/dobby-artifact {요구사항}  [key={오더키}]
```

- **{요구사항}** (필수) — 무엇을 담은 글을 원하는지. 예: `결제 실패 원인과 고친 방법을 팀에 공유할 문서로`
- **key={오더키}** (선택) — 주면 그 오더의 `artifact-share.md`에 기록돼 대시보드에서 바로 열 수 있다. 안 주면 링크만 알려준다(오더가 아닌 조사·회의 준비 세션에서도 쓸 수 있게).

## 슬러그

게시 원고 파일명이자 신규/갱신을 가르는 이름표다. **요구사항의 주제**에서 짧은 영문 슬러그(소문자·숫자·하이픈)를 정한다. 예: `결제 실패 원인` → `payment-failure`.

`key=`가 있고 그 슬러그 행이 **이미 있으면 갱신**이다 — Artifact 도구 `url` 인자에 그 행의 URL을 넘겨 같은 링크를 업데이트하고 `dobby_artifact_touch`로 기록한다. 없으면 신규로 게시하고 `dobby_artifact_add`로 행을 추가한다.

**⛔ 슬러그가 다르면 절대 기존 URL로 업데이트하지 마라** — 다른 주제의 아티팩트를 덮어써 이전 링크가 죽는다. 링크를 잃으면 되돌릴 수 없다.

## 절차

### A0. 근거 모으기 — 이번 세션에서 한 일만

이번 세션에서 **실제로** 읽은 코드·고친 파일·실행한 명령과 그 결과·사용자와 합의한 결론을 모은다.

- **⛔ 세션 밖 추가 조사 금지, 지어내기 금지.** 확인하지 않은 것을 "아마 이럴 것"으로 적지 않는다.
- 요구사항과 관계없는 일은 **뺀다**. 세션에서 한 일을 전부 늘어놓는 글이 아니다.
- 추측이 꼭 필요하면 **추측이라고 밝히고 그렇게 본 근거**를 함께 적는다.

세션에서 한 일이 없으면(막 시작한 세션 등) **중단하고** 무엇을 하고 나서 다시 부르면 되는지 알린다.

### A1. 담을 내용 확인받기 (게시 전 유일한 확인 지점)

무엇을 넣고 무엇을 뺄지 목록으로 보여주고 확인을 받는다. **아티팩트는 공개 후 되돌릴 수 없으므로** 여기서 한 번 끊는다.

```
담을 것:  ① 무엇이 문제였나  ② 원인  ③ 고친 방법  ④ 남은 확인
뺄 것:    · 중간에 접었던 다른 시도(결과물과 무관)
          · 도구 사정(아래 "배제" 규칙)
```

사내 민감 정보(계정·키·고객 데이터)가 들어갈 것 같으면 여기서 함께 확인한다.

### A2. 원고 작성

`$ORCHESTRATION_META/{키}/artifacts/{슬러그}.html`에 쓴다. `key=`가 없으면 `$ORCHESTRATION_META/.artifacts/{슬러그}.html`.

**반드시 지키는 3가지** — 아래 "기본 3규칙" 절을 그대로 따른다.

**⛔ Artifact CSP 준수 — 외부 호스트(CDN·폰트·이미지·스크립트) 금지, 모든 CSS는 `<style>`로 인라인.**
**mermaid 다이어그램**: 아티팩트는 외부 라이브러리를 못 받아와 라이브 렌더가 안 된다. 각 다이어그램을 **뜻이 보존되는 대체 표현**으로 바꾼다 — 간단한 흐름은 인라인 SVG나 번호 매긴 단계 목록·화살표 텍스트로, 표 형태면 HTML 표로.

### A3. 자동 검사 — 걸리면 스스로 고쳐 다시 (최대 2회)

```
dobby_tooling_lint {원고}   # 도구 이야기(이 플러그인·대시보드)
dobby_terms_lint   {원고}   # 내부 줄임말(FE/BE·round-N·P숫자·blocking=·K=)
```

둘 중 하나라도 걸리면 **걸린 줄을 고쳐 다시 검사한다.** 원고는 이 스킬이 직접 쓴 글이므로 고칠 수 있다 — 지우는 게 아니라 **뜻을 살려 옮겨 적는다**(아래 "바꿔 쓰는 법").

**2회 고쳐도 남으면 게시하지 않고 중단**한다. 걸린 줄을 그대로 보여주고, 그 내용을 빼도 되는지 사용자에게 묻는다. 코드 안 실제 식별자를 인용하는 정당한 예외만, 사용자가 시킨 경우 `DOBBY_FORCE=1`.

### A4. 게시

`artifact-design` 스킬 지침에 따라 그 HTML 파일을 **Artifact 도구로 publish**한다. `title`은 글의 주제를 담은 짧은 이름(키 번호가 아니라 **무엇에 대한 글인지**), `description`은 한 줄 요약, `favicon`은 `📄`. 반환된 **URL**을 확보한다.

### A5. 기록 — `key=`가 있을 때만 (헬퍼로만, 파일을 직접 쓰지 않는다)

- 신규: **`dobby_artifact_add {키} {슬러그} "{제목}" {URL}`**
- 갱신: **`dobby_artifact_touch {키} {슬러그} "{무엇을 바꿨나}"`**

`dobby_artifact_add`는 같은 슬러그 행이 있으면 아무것도 하지 않고 1을 반환한다 — 그 경우는 갱신이므로 `touch`를 쓴다.

### A6. 보고

링크를 보여주고, **무엇을 뺐는지 한 줄**로 알린다(도구 이야기 N곳 등). `key=`를 줬으면 대시보드 아티팩트 탭에서도 열린다고 안내한다.

## 기본 3규칙

### ① 목차

문서 머리에 **접히지 않는 목차**를 넣고 각 제목에 `id`를 달아 눌러 이동하게 한다.

```html
<nav class="toc">
  <h2>목차</h2>
  <ol>
    <li><a href="#what">무엇이 문제였나</a></li>
    <li><a href="#why">왜 그랬나</a></li>
    <li><a href="#how">어떻게 고쳤나</a></li>
  </ol>
</nav>
```

**절이 2개 이하면 목차를 넣지 않는다** — 목차가 본문보다 길어진다.

### ② 쉬운 용어

- 전문용어는 **처음 나올 때 괄호로 풀이**를 단다. 예: "캐시(한 번 받아온 것을 잠깐 저장해 두는 것)"
- **줄임말을 쓰지 않는다.** 풀어서 정확히 적는다(`FE`→프론트엔드, `BE`→백엔드).
- 코드 안 실제 이름은 그대로 두되 **무엇을 하는 것인지 한 줄**을 붙인다.
- 파일을 설명할 때는 **경로를 밝히고** 관련 코드 조각을 함께 보여 준다.

### ③ 도구 이야기 완전 배제 ⛔

**이 글을 읽는 사람은 이 도구를 쓰지 않는다.** 도구 사정은 작업 내용이 아니라 소음이다. 아래는 **한 줄도 넣지 않는다.**

| 묶음 | 넣지 않는 것 |
|------|--------------|
| 도구 이름 | `dobby` · `도비` · `go-dobby` · `/dobby-*` 스킬 이름 · `mentis` |
| 메타 파일 | `orchestration.md` · `status.md` · `explainer.md` · `artifact-share.md` · `design-ack` |
| 진행 구조 | 에이전트 상태표 · 칸반 · 슬러그 · 라운드 N · 블로킹 · 단계 이름(착수·구현·리뷰·검증 …) |
| 작업 공간 | 워크트리 · 오케스트레이션 메타 |
| 꾸밈 기능 | 소감 · 아바타 |
| 헬퍼 | `dobby_*` |

**'대시보드'라는 낱말 자체는 금지가 아니다** — 업무로 다루는 일반 대시보드를 가리키는 정상 문장이 걸린다(기존 산출물 145개 중 1건 실측). 이 도구를 가리킬 때만 `mentis`로 걸러진다.

#### 바꿔 쓰는 법 — 지우지 말고 뜻을 살려 옮긴다

```
✗ dobby-test로 브라우저 검증이 필요합니다
✓ 브라우저에서 직접 눌러 보는 확인이 남아 있습니다

✗ 작업 워크트리에 node_modules가 없어 타입 검사를 못 했습니다
✓ 의존성이 설치되지 않은 환경이라 타입 검사는 CI에서 확인해야 합니다

✗ 리뷰 라운드 2에서 지적받아 고쳤습니다
✓ (아예 뺀다 — 결과물을 읽는 사람에게 과정은 필요 없다)

✗ status.md의 단계를 해결로 바꿨습니다
✓ (아예 뺀다 — 도구를 쓰다 생긴 뒤처리다)
```

## 비파괴

- `artifacts/{슬러그}.html`과 (`key=`가 있을 때) `artifact-share.md`만 만들거나 갱신한다.
- **다른 슬러그의 행·원고는 건드리지 않는다.** 워크트리·코드·다른 메타·Jira는 건드리지 않는다.
- 세션에서 확인하지 않은 내용을 아티팩트에 넣지 않는다.

## 주의

- **대화형 전용**: 헤드리스/백그라운드에서는 Artifact 도구·claude.ai 인증이 없어 실패한다. 대시보드 버튼으로 자동화하지 않는다.
- 아티팩트는 기본 **비공개**로 게시된다(사용자가 claude.ai에서 공유 여부를 결정).
