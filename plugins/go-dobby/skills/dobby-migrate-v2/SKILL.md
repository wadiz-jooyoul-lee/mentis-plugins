# dobby-migrate-v2

`dobby-order` 로 진행하던 오더를 `/do` 로 옮긴다. 옮긴 뒤에는 `/do {키}` 또는 `run.sh {키}` 로 이어간다.

## 언제 쓰나

| 쓴다 | 쓰지 않는다 |
|---|---|
| 남은 단계가 길다(구현이 안 끝났거나, 리뷰와 수정이 몇 번 더 돌 것 같다) | 통합이나 검증만 남았다 — dobby-order 로 끝내는 편이 싸다. 옮기는 데도 세션 하나가 든다 |
| 지금 dobby-order 세션의 문맥이 커서 호출마다 비싸다 | 해결, 종료, 완료, 보류 단계다 — 헬퍼가 거부한다 |
| | 설계 문서 없이 분석 단계를 넘어갔다 — 헬퍼가 거부한다. v2 의 뒷세션은 설계 문서를 기준으로 일하기 때문이다 |
| | 착수 단계다 — 옮길 것이 없다. `/do {키}` 로 바로 시작한다 |

## 설정 (첫 실행 시 확인)

작업 전에 **`${CLAUDE_PLUGIN_ROOT}/reference/config.md` 의 "설정 절차"를 그대로 따른다**(config.env 는 읽기만). 이하 메타 경로는 `$ORCHESTRATION_META` 기준이고, 헬퍼는 `${CLAUDE_PLUGIN_ROOT}/reference/dobby-lib.sh` 의 `dobby_*` 를 쓴다.

v2 의 규칙은 `${CLAUDE_PLUGIN_ROOT}/skills/do/SKILL.md` 가 정본이다. 아래에서 "v2 의 1-3" 처럼 가리키면 그 문서의 그 절을 읽고 따른다.

## 1. 떠 있는 세션 확인

같은 오더를 맡은 dobby-order 세션이 아직 떠 있으면, 두 세션이 같은 메타 문서를 동시에 고친다. 그래서 **가장 먼저 사람에게 그 세션을 닫았는지 묻는다.** 닫지 않았다면 닫은 뒤 다시 실행하라고 알리고 끝낸다.

## 2. 옮길 수 있는지 검사

```
dobby_migrate_v2_check {키}
```

아무것도 고치지 않는다. 결과는 "항목, 값" 줄이다.

| 항목 | 뜻 |
|---|---|
| `단계` | 지금 단계값 |
| `불가` | 옮길 수 없다. 이유가 함께 나온다. 이 줄이 있으면 이유를 알리고 끝낸다 |
| `개발담당` | 상태표에서 이름이 "분석/개발자" 인 행. 없으면 전환 때 `v2-dev` 행을 만든다 |
| `진행중행` | 상태가 분석, 구현, 리뷰인 행. 전환 때 전부 대기로 돌린다 |
| `마지막리뷰` | 가장 최근 리뷰의 차수, 결과 파일 수, 막는 지적(`[blocker]`·`[major]`) 수 |
| `주의` | 리뷰가 이미 3차 이상이다. v2 는 3차를 넘기면 수정 뒤 멈추고 사람에게 넘긴다 |
| `확인` | 구현 단계인데 진행 중인 행이 있다. 구현이 끝났는지 사람에게 물어야 한다 |
| `필요` | v2 의 뒷세션이 읽는데 지금 없는 문서. 4절에서 채운다 |

결과를 **쉬운 말로 풀어** 사람에게 보여 준다. 그리고 옮긴 뒤 다음 세션이 무엇을 하게 되는지 한 줄로 덧붙인다(6절의 표).

`확인` 줄이 있으면 함께 묻는다. **"구현이 끝났나요?"**
- dobby-order 의 `구현` 단계는 "구현 중"이라는 뜻이고, v2 의 `구현` 단계는 "구현을 마쳤다"는 뜻이다. 그래서 그대로 두면 v2 가 남은 구현을 건너뛰고 바로 리뷰로 간다.
- 사람이 모르겠다고 하면 **안 끝난 것으로** 본다. 그쪽은 설계를 한 번 더 확인받고 구현 세션을 거치므로, 할 일을 빠뜨리지 않는다.

사람이 진행하라고 하면 3절로 간다.

## 3. 기계적인 전환

```
WT="$(dobby_migrate_v2_apply {키} {구현미완료})"
```

`구현미완료` 는 2절에서 구현이 안 끝났다고 답했으면 `1`, 그 밖에는 `0` 이다. 헬퍼가 하는 일은 아래와 같다.

| 하는 일 | 왜 |
|---|---|
| 상태 문서의 워크트리마다 `dobby_ensure_worktree` 를 부른다. 폴더가 지워졌으면 남은 브랜치로 되살린다 | 뒷세션이 그 폴더에서 코드를 고친다 |
| 개발 담당 행이 없으면 `v2-dev` 행을 만든다 | v2 의 개발 세션은 이 행의 슬러그를 쓴다 |
| `dobby_session_log` 로 `## 지난 세션` 표를 만든다. 원래 세션 아이디는 "이전 세션" 줄로 옮겨진다 | 이 표가 v2 오더의 표지다. 원래 세션은 나중에 `claude --resume` 으로 복기할 수 있다 |
| 진행 중인 행을 전부 대기로 돌린다 | 세션 사이의 빈 시간에 보드가 "정체"로 경고하지 않게 한다 |
| 구현미완료가 `1` 이면 단계를 `분석` 으로 되돌린다 | 다음 v2 세션이 설계를 보여 주고 확정받은 뒤 구현 세션으로 간다 |
| 구현이 끝났고 마지막 리뷰 폴더에 결과가 있으면, 다음 차수의 빈 리뷰 폴더를 연다 | v2 리뷰 세션은 가장 큰 차수 폴더에 쓴다. 열지 않으면 옛 리뷰 결과를 덮어쓴다 |
| 이벤트 로그에 전환 사실과 전후 단계를 남긴다 | 보드에서 언제 옮겼는지 보인다 |

헬퍼가 실패하면 오류 문장을 그대로 사람에게 보여 주고 멈춘다. 특히 "git 에 등록되지 않은 폴더" 오류는 사람이 그 폴더를 확인해야 한다.

## 4. 빠진 문서 채우기

`dobby_migrate_v2_check` 의 `필요` 줄에 나온 것만 채운다. **기존 문장은 지우거나 줄이지 않는다. 절을 덧붙인다.** 이미 있는 분석 문서, 설계 문서, 구현 문서, 리뷰 결과를 근거로 쓰고, 모자라면 워크트리(`$WT`)의 코드를 직접 읽는다. 추측으로 채우지 않는다.

### 설계 보강

v2 의 1-3 "반드시 더 적는 것"을 따라 `design.md` 에 없는 절을 덧붙인다.
- `## 작업 순서`
- `## 건드리지 않을 것`
- `## 검증 명령` — 저장소에 실제로 있는 명령인지 확인하고 적는다

**구현이 안 끝나서 단계를 분석으로 되돌린 경우에는** `## 작업 순서` 맨 앞에 "이미 된 것"과 "남은 것"을 나눠 적는다.
- 근거는 세 가지다. 구현 문서, 상태표의 각 행 설명, 워크트리의 변경(`git -C "$WT" status` 와 `git -C "$WT" diff --stat`)이다.
- 이렇게 적지 않으면 구현 세션이 이미 된 일을 다시 하거나, 남은 일을 모른 채 끝낸다.

### 리뷰 항목

v2 의 1-3 "`## 리뷰 항목` 절" 형식대로 `design.md` 맨 끝에 덧붙인다.
- 이미 끝난 리뷰 결과(`reviews/round-*/`)에서 되풀이된 지적은 "이 변경에서 틀리기 쉬운 곳"의 좋은 재료다.
- 호출부는 그 절의 "호출부를 찾는 법"대로 직접 찾는다.

### 테스트 계획

v2 의 1-4 형식대로 `test-plan.md` 를 쓴다.
- 각 시나리오의 `- **조건**:` 값은 상태 문서의 `## 닫히는 조건 항목` 표에서 가져온다.
- 그 표가 없으면 설계 문서의 `## 닫히는 조건` 을 보고 `dobby_add_condition {키} "{조건 한 줄}"` 로 먼저 만든다.
- 이미 테스트를 돌린 기록(`test-runs/`)이 있으면, 그때 확인한 시나리오와 실패한 시나리오를 빠짐없이 옮긴다.

### 점검

채운 문서만 v2 의 1-5 표로 점검하고, `dobby_lint {키}` 와 `dobby_terms_lint $ORCHESTRATION_META/{키}/design.md` 를 돌려 걸리는 것을 고친다.

## 5. 마무리

```
dobby_event {키} "v2 전환 문서 보강 완료 — {채운 것}"
```

## 6. 세션 닫기

v2 의 "세션을 닫는 법" 형식 그대로 알리고 **더 이상 아무것도 하지 않는다.** "다음" 칸에는 아래 표에서 지금 단계에 맞는 줄을 쓴다.

| 전환 뒤 단계 | 다음 v2 세션이 하는 일 |
|---|---|
| 분석 (설계 문서 없음) | 분석 문서부터 다시 설계하고 사람과 확정한다 |
| 분석 (설계 문서 있음) | 설계 요약을 보여 주고 사람과 확정한다. 확정한 뒤에는 `run.sh {키}` 로 남은 단계를 자동으로 돌릴 수 있다 |
| 구현 | 리뷰 |
| 리뷰 | 막는 지적이 남았으면 수정, 없으면 통합 |
| 통합 | 검증(배포가 끝난 뒤에) |
| 검증 | 검증 결과에 따라 수정 또는 끝 |

## 하지 않는 것

- **코드를 고치지 않는다.** 구현과 수정은 v2 의 뒷세션이 한다.
- **커밋하지 않는다.**
- **기존 리뷰 결과, 구현 문서, 이벤트 로그를 지우거나 고쳐 쓰지 않는다.** 덧붙이기만 한다.
- **`dobby-order` 스킬 문서를 고치지 않는다.**
- **다음 단계를 이어서 하지 않는다.** 이 세션은 옮기는 데까지만 쓴다.
