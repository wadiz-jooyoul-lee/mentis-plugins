# dobby-auto

착수부터 검증까지 **한 번 부르면 끝까지** 간다. 사람은 막혔을 때만 부른다.

```
dobby-order (light · design=auto)  →  dobby-ship  →  dobby-test  →  알림
```

⛔ **세 스킬을 다시 쓰지 않는다.** 그대로 부른다. 이 스킬이 맡는 것은 **이어 붙이기와 멈춤 처리**뿐이다. 한쪽을 고쳐도 다른 쪽이 따라 흔들리지 않게 하기 위해서다.

## 인자

```
/dobby-auto {키|URL} {dev|rc1|rc4|stage}
```

`dobby-ship` 과 같은 규칙으로 가른다 — 네 환경 이름 중 하나면 환경, 그 밖이면 대상 오더다. 순서는 상관없다. 환경이 없으면 묻고 멈춘다(어디로 내보내는지는 사람이 정할 일이다).

## 0. 이어서 할 자리 찾기

`status.md` 의 `## 배포` 표에서 이번 환경 행을 본다. 있으면 그 단계 다음부터, 없으면 1번부터. 중간에 끊겨도 같은 명령을 다시 부르면 이어 간다.

## 1. 구현까지 — `dobby-order`

```
/dobby-order {키} light design=auto
```

- **`light`** — 착수·분석·구현을 메인이 인라인으로 한다. 서브 에이전트는 **리뷰어 1명뿐**이다.
  - ⛔ 리뷰어는 줄일 수 없다(→C5 리뷰어≠구현자). 자기가 쓴 코드를 자기가 리뷰하면 의미가 없다.
  - `light` 는 원래 소규모 단일(K=1) 전용이지만, **이 스킬에서는 규모와 상관없이 쓴다** — 사람이 안 보는 동안 에이전트를 늘리는 것보다 토큰을 아끼는 편이 낫다.
  - **⛔ 문맥이 차오르면 그때는 서브로 바꾼다.** 메인 문맥이 무거워지면 요약이 끼어들어 앞부분을 잃는다. 분석 결과가 여러 저장소·여러 영역으로 번지면 일반(서브) 모드로 전환하고 그 사실을 이벤트 로그에 남긴다.
- **`design=auto`** — 설계 승인(확인 게이트 #6)을 건너뛴다. 대신 확인이 필요했던 것을 스스로 정하고 **결정과 이유를 `design.md` 에 반드시 남긴다**(이유 없는 결정은 lint 치명).
- **`mode=B` 를 쓰지 않는다.** Workflow 병렬은 속도를 위해 에이전트를 늘린다. 자동 실행은 사람이 안 보고 있으니 속도보다 토큰이 중요하다.

통합(P7)까지 끝나면 2번으로 간다.

## 2. 배포까지 — `dobby-ship`

```
/dobby-ship {키} {환경}
```

**⛔ `dev`·`rc1`·`rc4` 의 머지와 빌드를 묻지 않는다.** `dobby-ship` 은 이 둘을 반드시 묻지만, 이 스킬이 부를 때는 묻지 않고 진행한다. 되돌리기 쉬운 환경이고, 막는 것은 헬퍼와 훅이 이미 하고 있다.

| 그래도 막히는 것 | 무엇이 막나 |
|---|---|
| `stage` 머지 | 훅 G1 — 시점은 사람이 고른다. PR 까지만 만들고 알린다 |
| `cloud_live` | 훅 G1 — 절대 |
| 반영 안 한 변경요청 | `dobby_ship_merge` |
| 리뷰 4라운드째 | `dobby_ship_round` |

## 3. 충돌 — 멈추지 않고 직접 푼다

**⛔ PR 은 언제나 다리 브랜치(`{브랜치}_into_{환경}`)로 만든다.** 충돌이 없어도 그렇게 한다. `dobby_ship_pr` 이 그렇게 돼 있다.

`dobby_ship_pr` 이 충돌로 거부하면 임시 워크트리 경로를 함께 준다. 거기서 푼다 — **오더 워크트리는 건드리지 않는다.**

```bash
# ① 양쪽이 왜 그 부분을 건드렸는지 본다 (파일마다 이력·diff 를 한 번에)
dobby_conflict_evidence {임시워크트리} {브랜치} {환경}

# ② 근거로 판단해 직접 고친다  (아래 규칙)

# ③ 검증하고 올린다
dobby_bridge_finish {임시워크트리} {브랜치} {환경}
```

### 어떻게 고르나

⛔ **근거 없이 한쪽을 고르지 않는다.** ①이 준 이력·diff 로 양쪽의 **의도**를 먼저 읽는다. 커밋 메시지에 이슈 키가 있으면 그 이슈의 목적까지 본다. 저장소 `CLAUDE.md` 에 충돌 규칙이 있으면 그것이 먼저다.

| 유형 | 판별 | 해결 |
|---|---|---|
| 독립 추가 | 인접한 위치에 서로 다른 항목을 추가, 내용이 안 겹침 | 둘 다 유지 |
| 나열형 파일 | import·index 의 export·라우트 등록·i18n 키·enum | 합집합, 순서는 그 파일의 기존 방식 |
| 한쪽만 의미 변경 | 한쪽은 포맷·이동·정렬만, 다른 쪽만 로직 | 로직 변경을 채택하고 포맷을 적용 |
| 생성 파일 | 잠금 파일 등 명령으로 다시 만들 수 있는 것 | 병합 후 그 명령으로 재생성 |
| 규칙 명시 | `CLAUDE.md` 에 해결법이 적혀 있음 | 그 규칙 그대로 |
| **같은 줄을 다르게 고침** | | 근거로 의도가 확정되면 고르고, **확정 안 되면 멈추고 묻는다** |
| **삭제 ↔ 수정 · 이름 변경 충돌 · 바이너리** | | 같다 — 확정되면 고르고, 아니면 멈추고 묻는다 |

**멈추고 물을 때는 "어떻게 할까요"가 아니다.** 해결안을 만들어 놓고 근거와 함께 승인만 받는다.

```
FE1-1787  충돌 1건 — 판단이 서지 않습니다

파일     packages/api/src/web/social.service.ts:42
내 쪽    친구 목록에 blocked 필드 추가 (FE1-1787 — 차단 목록 분리)
환경 쪽  같은 줄을 followedAt 으로 교체 (FE1-1990 — 정렬 기준 변경)
권장안   둘 다 유지 — 서로 다른 목적이고 타입이 겹치지 않습니다
확인 필요 두 이슈가 같은 API 응답을 쓰는지 확인하지 못했습니다
```

### 자동 해결이 통과해야 하는 검증

`dobby_bridge_finish` 가 셋을 본다. 하나라도 걸리면 **아무것도 올리지 않고** 임시 워크트리를 남긴다.

```
① 충돌 표시자가 남아 있나        <<<<<<< ======= >>>>>>>
② 스테이지가 깨끗한가            git diff --cached --check
③ 저장소 고유 금지 규칙          dobby_repo_lint
```

**④ 의도 보존은 기계가 못 가린다 — 직접 확인한다.** 자동으로 푼 파일마다, 양쪽이 추가·수정한 핵심 식별자(함수명·상수명·키 이름)가 결과에 **모두 남아 있는지** 본다. 한쪽이 사라졌다면 왜 버렸는지 ①의 근거로 설명할 수 있어야 한다. 설명할 수 없으면 **멈추고 묻는다.**

### 남기는 것

승인을 안 받는 대신 무엇을 왜 그렇게 골랐는지 세 곳에 남긴다.

```
PR 본문           ## 충돌 처리 — 파일 · 양쪽 의도 · 고른 것 · 근거
orchestration.md  - {일시} 충돌 자동 해결 — {파일 n개}, {한 줄 근거}
알림              같은 줄 충돌처럼 원래 승인을 받던 유형은 따로 표시한다
```

## 4. 리뷰를 기다릴 때 — `rc1` · `rc4`

```
 0~10분   30초 간격 폴링 (dobby-ship 4단계 그대로)
 10분     ① 리뷰어가 붙었나 먼저 본다 — 안 붙었으면 붙이고 시계를 리셋
          ② 붙어 있는데도 없으면 알리고(6번) 백그라운드 감시로 넘긴다
10~30분   셸이 2분 간격으로 본다
 30분     그만두고 알린다
```

감시는 **`Bash` 를 `run_in_background` 로** 띄운다. 조건이 참이 되거나 30분이 지나면 종료하고, **그때 한 번만** 깨어난다.

```bash
end=$((SECONDS + 1800))
while [ $SECONDS -lt $end ]; do
  d="$(gh pr view {PR} --json reviewDecision -q .reviewDecision 2>/dev/null)"
  [ -n "$d" ] && { echo "리뷰 도착: $d"; exit 0; }
  sleep 120
done
echo "30분 무응답"; exit 1
```

⛔ **`Monitor` 를 쓰지 않는다.** 줄마다 알림이 와서 그만큼 왕복이 는다. 여기서 알아야 하는 것은 "달렸나 / 30분 지났나" 하나뿐이다. 기다리는 동안 토큰은 **0** 이다 — 셸만 돈다.

## 5. 검증 — `dobby-test`

```
/dobby-test {키} {환경}
```

**실패하면 멈추고 알린다.** 자동으로 고치러 돌아가지 않는다 — 검증 실패는 원인이 제각각이라(FE1-1808 은 반쪽 배포, FE1-2005 는 번역 누락) 자동 수정이 오히려 시간을 쓴다.


⚠ 두 연결 모두 대화형 로그인이 필요해 끊겨 있을 수 있다. **터미널 출력과 `## 배포` 표 기록은 언제나 남기고**, 메일·DM 은 그 위에 얹는다. 보내기에 실패하면 실패했다고 터미널에 적는다.

## 멈추는 자리 — 전부

```
stage 머지            시점은 사람 (훅 G1)
cloud_live            절대 (훅 G1)
충돌 판단 불가         해결안을 만들어 알리고 멈춤
충돌 해결이 검증 실패   임시 워크트리를 남기고 멈춤
반영 안 한 변경요청     dobby_ship_merge 가 거부
리뷰 4라운드째         dobby_ship_round 가 거부
리뷰 30분 무응답       알리고 멈춤
검증 실패             알리고 멈춤
제품·디자인 결정       코드로 확정 불가 — 알리고 멈춤
```

밑에서 다섯은 **글이 아니라 헬퍼·훅이 거부**로 막는다. 이 스킬이 실수로 넘어갈 수 없다.

## 무엇이 코드로 강제되나

| 강제되는 것 | 어디서 |
|---|---|
| cloud_live 로 가는 모든 것 | 훅 G1 |
| 머지 베이스가 dev·rc1·rc4 인지 | 훅 G1 + `dobby_ship_merge` |
| PR 은 언제나 다리 브랜치로 | `dobby_ship_pr` |
| 충돌 표시자·스테이지 오염·저장소 규칙 | `dobby_bridge_finish` |
| 리뷰 왕복 4회 이상 | `dobby_ship_round` |
| 배포 단계 어휘·환경 | `dobby_ship_stage` |
| 파일 쓰는 순간 저장소 금지 규칙 | 훅 G14 |

**여기 없는 것은 판단이라 강제할 수 없다** — 충돌에서 어느 쪽 의도가 맞는가, 문맥이 찼는가. 그건 이 문서가 맡는다.

## 주의

- **추측하지 않는다.** 충돌 해결도 리뷰 판단도 근거를 대고 한다. 부득이 추측이 섞이면 추측이라 밝히고 근거를 댄다.
- **한 번에 다 못 해도 된다.** 기다릴 수 없는 곳에서 깨끗이 멈추고 `## 배포` 표에 단계를 남기는 편이, 억지로 진행하는 것보다 낫다.
- 진행 상황은 **한국어와 존댓말**로 적는다.
