# dobby-auto

설계부터 배포 환경 검증까지 **한 번 부르면 끝까지** 간다. 사람은 판단이 필요할 때만 부른다.

이 스킬은 `/do` 의 자동 배포 오더로 들어가는 문만 맡는다. 실제 진행 규칙은 `/do` 스킬과 `skills/do/auto-mode.md` 에 있다. 예전에는 dobby-order 위에서 한 세션으로 끝까지 갔지만, dobby-order 를 쓰지 않기로 해서 `/do` 로 옮겼다. 명령 이름은 사람이 익힌 그대로 둔다.

## 인자

```
/dobby-auto {키|URL} {dev|rc1|rc4}
```

`dobby-ship` 과 같은 규칙으로 가른다. 환경 이름이면 환경, 그 밖이면 대상 오더다. 순서는 상관없다. 환경이 없으면 묻고 멈춘다. 어디로 내보낼지는 사람이 정할 일이다.

## 오더 상태에 따라

`$ORCHESTRATION_META/{키}/status.md` 를 보고 고른다.

| 오더 상태 | 할 일 |
|---|---|
| 환경이 `stage` | 받지 않는다. stage 는 `/dobby-ship {키} stage` 로 PR 까지만 만들고 사람이 머지·배포한다고 알린다 |
| 환경이 `clive`·`cloud_live` | 받지 않는다 |
| 메타가 없다, 또는 단계가 `착수` | `do` 스킬을 `{키} auto env={환경}` 인자로 부른다. 설계 세션이 설계를 스스로 확정하고, 사전 확인 뒤 자동 실행을 띄운다 |
| v2 오더(`## 지난 세션` 표가 있다)이고 설계가 확정됐다 | 아래 "이미 진행 중인 v2 오더" |
| v2 오더인데 설계가 확정되지 않았다 | `do` 스킬을 `{키} auto env={환경}` 인자로 부른다 |
| dobby-order 로 진행한 오더(`## 지난 세션` 표가 없고 단계가 `착수` 도 아니다) | 아무것도 고치지 않고 멈춘다. `/dobby-migrate-v2 {키}` 로 옮긴 뒤 다시 부르라고 알린다. 두 스킬이 한 오더를 번갈아 맡으면 서로의 기록을 잘못 읽는다 |
| 해결·종료·완료 | 끝난 오더라고 알리고 멈춘다. 다시 고치려면 `/do {키} 변경 {내용}` |

"설계가 확정됐다"는 `/do` 단계 판정과 같다. `design-ack.json` 의 `사용자` 또는 `auto` 값이 `dobby_design_rev {키}` 와 같으면 확정이다.

## 이미 진행 중인 v2 오더

설계 세션 없이 자동 실행만 띄운다.

1. `/do` 1-7 의 `env=` 사전 확인 표를 그대로 돈다(환경 값, 저장소, gh 로그인, argocd 로그인, 테스트 계정). 하나라도 안 되면 무엇이 빠졌는지 알리고 멈춘다.
2. `dobby_v2_set_env {키} {환경}`
3. `dobby_v2_autorun {키}`. 결과 처리는 `/do` 1-6 의 표와 같다.

⛔ 이 세션에서 `run.sh` 를 직접 띄우거나 다음 단계를 이어서 하지 않는다. 이 세션 아래에서 띄운 프로세스는 세션이 닫힐 때 함께 끝날 수 있다.

## 끝낼 때

자동 실행을 띄웠으면 아래처럼 알리고 끝낸다.

```
{키} · 자동 실행 시작 ({환경})
  - 구현부터 {환경} 배포와 검증까지 자동으로 이어 갑니다.
  - 진행 상황은 대시보드 {키} 오더 화면에서 볼 수 있습니다. 이 세션은 닫아도 됩니다.
  - 끝나거나 판단이 필요하면 슬랙과 메일로 알립니다.
```
